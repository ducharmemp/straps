# Security policy

## Reporting a vulnerability

Do not open a public issue for an unpatched vulnerability.

Use GitHub's private vulnerability reporting for this repository. Include the affected version, reproduction steps, impact, and any proposed fix.

## Security model

Straps is not a sandbox. Approved shell commands, Lua evaluation, file changes, and trusted `.straps.lua` files run with the Neovim process's user privileges.

### Session extension permissions

The `lua` category permits structurally valid session-local `registry_define` requests for tools, hooks, and functions, plus calls to session-scoped tools without explicit trusted capability metadata. Session-local skills use the permission-free `read` category, although defining one mutates the session registry. Direct global definitions, malformed or unclassified definition requests, and definitions of `hook.confirm`, `fn.capability`, `fn.readonly_policy`, `tool.registry_define`, `hook.guard`, or `hook.guard.*` use `define`. Those direct requests require confirmation; `registry_define` offers no blanket “Always this tool” approval and ignores tool-name grants. A session shadow of `tool.registry_define` also remains `define` when invoked. Unknown global tools remain `agent_tool`.

These rules classify dispatched direct requests. Arbitrary Lua still runs with process privileges and can call registry APIs; the protected-name checks do not sandbox approved Lua. Guard freezing and guard vetoes remain independent of confirmation. A restricted child with `lua` may define and invoke ordinary session extensions; a readonly child may define session skills. A bare `allow={"registry_define"}` is denied. Contextual dispatch retains ancestor ceiling checks and definition identities. Transcript excision permissions are unchanged. Combined manual approval for defining and using an extension is deferred.

### Edit-category substitution

`bulk_replace` is in the `edit` category, so an "Always all edits" grant approves it without a prompt. It never builds a `:s` command from agent text that Vim could read as code or as extra command text. The pattern goes into the search register with `setreg()` and stays out of the command line. The replacement is refused when it starts with `\=` (a Vimscript expression) or `~` (the previous replacement, which can hold an expression), ends in an unescaped backslash, or contains a newline, a carriage return, `|` or a NUL byte. The pattern is refused when it contains a newline, a carriage return, `|` or a NUL byte. A replacement that contains every candidate delimiter is refused. The command runs as `smagic`, so `\~` is literal whatever `'magic'` is set to. The `:s` delimiter is the first of `# @ ! % , ; : ^ $ * + = ? / -` absent from the replacement. The tool runs every check before its `dry_run` return. After the substitution it restores the search register's text, `v:searchforward` and `v:hlsearch`; `setreg()` cannot restore the previous search's offset (`/abc/e`), its `'magic'` state or the smartcase override that `*` sets, so `n` after the tool uses the pattern with default flags. The permission preview counts the findings-list entries and files when the request is made. When a prompt approves the call, the tool compares the findings list at execution with the one the prompt counted, and refuses with a message to call `bulk_replace` again when they differ, for example when another call in the same batch replaced the list. A call approved by an earlier grant shows no preview and is not compared.

The session buffer's `@` file completion refuses text that contains a backtick, because Vim's file completion runs a backtick command (`` `cmd` ``) or expression (`` `=expr` ``) found in it, and a draft can hold text quoted from a transcript.

### Deferred permission review

With `permission_review = "deferred"` (the default), a run's permission request is listed in the corner float instead of a blocking dialog, so the editor stays usable while it waits; `gy` or `:StrapsPermission` opens the review float. The corner float builds each row from the first line of each field, and the review float shows the preview line by line, with control characters made printable in both. A file edit's preview starts with its `d:` and `p:` grant directories, ahead of the call's fields, so a field value cannot push them out of view. When the preview has more rows than the review float, its footer starts with `<n> of <m> rows shown, scroll`, so a long call cannot hide its end below the decision keys without notice. Neither float takes text from the transcript or calls `fn.render` or another registry renderer, so a session redefinition cannot change what you approve. Review refuses inside the command-line window and while any tool body is executing; a body suspended in `ctx.await` does not block review. The review does not protect against code you already approved. Once a session has had a `lua`, `define` or `exec` call approved, once or by a grant, that code can queue keystrokes (`nvim_feedkeys`, `nvim_input`), leave a timer, a scheduled callback or a coroutine that decides a later request, or drive Neovim over its RPC socket from a shell command. The modal dialog has the same exposure, since typeahead can answer it. Set `permission_review = "modal"` to restore the blocking dialog.

Contextual consent revalidates a pending request against the directory of the window that was current when the gate ran, so a `:tcd` in another tab does not invalidate it; a directory change in that window does. Once that window closes, refresh compares the current window's directory. Deciding a confirmation from a window with a different `:lcd` or `:tcd` resumes the run there, the execution-time check refuses the approved call with "execution directory changed", and a grant chosen in that decision stays recorded.

### Tool-call guards

`hook.guard.*` entries run before and after every tool call and before every registry define/remove. They are installed from `stdpath("config")/straps/init.lua`, frozen before the first run, and stored outside the registry's public surface, so the agent cannot define, redefine, remove, or shadow one through any tool. No guard ships; see `:help straps-guards`.

A guard enforces policy at the call site; it does not limit what already-approved code can do. Once the user approves an arbitrary `eval_lua` or `bash` call (or grants the `lua`/`exec` category), that code runs in the same Lua state and can reach the guard chain through `debug.*`, `ffi`, `package.loaded`, `load()` of an entry's `source`, the Neovim server socket (`$NVIM`), or by editing the session transcript. A hash-trusted `.straps.lua` has the same reach. Straps does not harden against these; a guard classifying `eval_lua`/`bash` input is where such attempts are visible. The transcript is not tamper-evident under those grants, so a guard verdict is enforcement at the call site only.

`stdpath("config")/straps/init.lua` loads with no trust prompt. Treat writes to it, and to the trust store under `stdpath("data")/straps/`, as privileged.

Provider endpoints receive API credentials and complete conversation payloads. Configure custom endpoints only when you trust their operator. A `llamacpp_base_url` or other custom endpoint over `http://` sends the key and the conversation unencrypted, and anyone on the network path can read them or alter the response, including the tool calls it requests; reach a remote server over TLS or an SSH tunnel to `127.0.0.1`.

`:StrapsLogin anthropic`, `:StrapsLogin openai key` and `:StrapsLogin llamacpp` store an API key in `$XDG_CONFIG_HOME/straps/<provider>_api_key` (mode 600, directory 0700). Straps ignores a relative `$XDG_CONFIG_HOME` (the XDG spec requires it) and a relative `$HOME`, so the store never resolves inside the working directory. Straps sends the key to the provider's configured base URL. For llama.cpp that is `llamacpp_base_url`, a remote `http://` server included. A key file accessible by group or other, or whose key contains spaces, control characters or non-ASCII characters, is refused.

A key typed by mistake as a command argument is removed from command history, but Neovim's `:` register keeps that command line until you run another command line; it is not written to ShaDa.

A stored key also overrides a key in the provider's environment variable, including one meant for a different base URL: straps does not record which endpoint a stored key belongs to. `:StrapsLogin` names any set key variable that the stored key overrides, and `:checkhealth straps` reports the key's source (`stored`). A symlinked key file (for example one a secret manager links into place) is read through, but straps never replaces or deletes it.

`$XDG_CONFIG_HOME/straps/` holds secrets: the stored API keys and the ChatGPT login. Keep it out of a dotfiles repository or sync tool that tracks `~/.config`; mode 600 does not stop `git add`. The default permission layer classifies `read_file` and the other read tools as `read` for every path, the key files and `/proc/self/environ` included, so the model can read a stored key without a prompt and the key then enters the transcript and the provider request. Install a `hook.guard` (`:help straps-guards`) that denies reads under that directory if that matters to you.

`:StrapsLogin openai` stores a ChatGPT access token and refresh token in `$XDG_CONFIG_HOME/straps/openai_oauth.json` (mode 600, directory 0700) and uses `openai_oauth.lock` beside it to serialise refreshes across Neovim processes. The refresh token grants ongoing access to the ChatGPT account's API quota; treat the file like a private key. Straps sends the login token only to `https://api.openai.com` (a configured `https://api.openai.com/v1` counts as the same origin) and refuses it for a custom `openai_base_url`. OAuth codes, verifiers and refresh tokens go to curl on stdin, not argv. Provider authentication headers go through exclusively created mode-600 temporary files instead of curl arguments. The transport removes each file on process exit, cancellation, wait, or spawn failure. Provider curl and compression subprocesses do not inherit `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `LLAMACPP_API_KEY`, or `LLAMA_API_KEY`. Curl's default config is disabled. Same-user file access, root, and process-memory inspection can still expose credentials. Abrupt Neovim termination can leave a private temporary file behind.

Session transcripts persist under Neovim's data directory by default. They can contain prompts, source code, and tool output.
