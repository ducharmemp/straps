1. INTRODUCTION						*straps-introduction*

straps.nvim is a small, legible harness for coding agents that live inside
Neovim. Three invariants govern the whole design:

1. Buffers are state. The conversation transcript IS a buffer in a parseable
   marker format. Each turn the loop re-parses the buffer to build the API
   request, so editing history, the system prompt, or an old message is a
   first-class action — the buffer is canonical.

2. Everything is late-bound and redefinable. Every tool, hook, the provider
   and the key loop functions are entries in a registry, stored as Lua source
   strings, compiled on define and looked up by name at every call. A
   redefinition takes effect on the very next call, even mid-run.
   See |straps-registry|.

3. The agent can extend itself. The agent has registry introspection and a
   define tool, and the tool list sent to the API is rebuilt from the registry
   every call, so a tool the agent defines in one turn is callable the next.

Requirements: Neovim >= 0.11 and `curl` on $PATH. Ripgrep is optional.
Run |:checkhealth| straps to verify your install — see |straps-health|.

2. SETUP						*straps-setup*

						*straps.setup()*
>lua
	require("straps").setup({
	  default_max_tokens = 32000,
	})
<
`setup()` merges your options into |straps-config|, then registers the default
provider, tools, editor tools and UI. It is idempotent: registration uses
`define_default`, which skips names that already exist, so a redefinition
(yours or the agent's) survives a re-run of `setup()`.

Every provider reads its key the same way: the key stored by |:StrapsLogin|
(|fn.api_key_store|, `$XDG_CONFIG_HOME/straps/<provider>_api_key`, which must
be chmod 600) first, then the environment. |fn.anthropic_api_key| reads
`$ANTHROPIC_API_KEY`; |fn.openai_api_key| tries a ChatGPT login, then a Codex
login, made with |:StrapsLogin| before the stored key, then reads `$OPENAI_API_KEY`;
|fn.llamacpp_api_key| reads `$LLAMACPP_API_KEY`, else `$LLAMA_API_KEY` (the
variable `llama-server` reads). The llama.cpp key is optional: `llama-server`
needs one only when it runs with `--api-key`. Anthropic sends the key as
`x-api-key`, OpenAI and llama.cpp as `Authorization: Bearer`.

The commands work without `setup()`: the first straps command run while the
registry has no `fn.provider` calls `setup()` with no options. Call `setup()`
yourself, before any command, to pass options.

3. COMMANDS						*straps-commands*

							*:Straps*
:Straps[!] [{cats}] [-- {instruction}]
			Open a new session buffer in a split and put the
			cursor on the trailing user block. See
			|straps-session|. {cats} pre-grants permission
			categories to the new session (comma or space
			separated; `all` grants every grantable category), the
			same grants |:StrapsAuto| makes. Text after `--` seeds
			the user block. `!` sends that block at once (a
			"nothing to send" notice when it is empty). An
			unknown category is an error and opens nothing.

			From the shell, this starts Neovim in a working
			session: >sh
	printf 'context' | nvim - +'Straps! edit,exec -- fix the failing test'
<			Two things happen only during startup (inside `+cmd`
			or `-c`): the text piped to `nvim -` is appended to
			the seeded request (after a blank line; whitespace-only
			input is dropped) and its buffer is wiped, and when
			no window modifier was given and the startup window
			shows that stdin buffer or the empty [No Name] buffer,
			the session takes it over instead of splitting.
			`nvim file +Straps` and `nvim +'vertical Straps'`
			split. Piped text is escaped like any block content,
			so a line that reads as a transcript marker cannot
			forge a block. A plugin manager that loads straps on
			first use of the `Straps` command sources the plugin
			after Neovim read stdin, so the piped text is not
			captured; load straps at startup to use it.
			|:StrapsResume| takes no categories or instruction;
			use |:StrapsAuto| on a resumed session.

							*:StrapsResume*
:StrapsResume [{name}]	Resume a saved session. No argument resumes the most
			recent; an argument is a session basename (completed
			from saved sessions) or a path. This reopens a
			transcript from disk; it does not restart a run — for
			that see |:StrapsContinue|. With no saved sessions,
			it and |:StrapsResume!| warn and open a new session.
			A window in the current tab already showing the
			session gets focus; otherwise |<mods>| place the new
			window as for |:Straps|.
:StrapsResume!		Open a picker over all saved sessions. Each row shows
			the session's durable title (see |:StrapsRename|) or,
			absent one, its first user prompt, plus a relative age
			— so sessions are identified by what they were about,
			not by a timestamped filename. With snacks.nvim present
			the picker fuzzy-matches those rows and previews the
			transcript; otherwise it is a |vim.ui.select| list.

							*:StrapsRename*
:StrapsRename [{title}]	Give the current session a durable title, stored in a
			companion "<transcript>.meta" file (the transcript
			itself is untouched). The title is what |:StrapsResume!|
			shows for the session. No argument prompts for one
			(pre-filled with the current title); an empty title
			clears it.

							*:StrapsSearch*
:StrapsSearch {pattern}	Full-text search across every saved transcript for
			{pattern} (ripgrep in the background when available,
			else a Vim |regexp| scan) and load the conversation
			matches — transcript scaffolding is skipped — into a
			new |quickfix| list, so |:cnext| / |:cprev| step through
			them and <CR> opens the transcript at the hit. Finds a
			session by what was said in it. No hits warns and
			leaves the quickfix list unchanged; an rg failure or an
			invalid pattern is reported as an error.

							*:StrapsOutline*
:StrapsOutline		From a transcript, open a reading tab showing the same
			buffer. Earlier turns fold under numbered first lines
			of their prompts. Press |zo| to reveal the original
			prompt, response and tool output in place. The latest
			turn and draft stay open. New turns remain unfolded
			until you reopen the reading tab. Use :StrapsOutline
			or |:close| there to return to the prior view.

							*:StrapsSend*
:StrapsSend		Send the current request. During a run or when a
			nonblank steering draft exists, open the draft. In the
			steering split, submit it (|straps-steering|). Also
			bound to <CR> in a session buffer. Warns "nothing to
			send" and starts no run if the trailing user block is
			empty, or if the transcript ends on an assistant
			message (unsupported prefill).

							*:StrapsSteer*
:StrapsSteer [text]	Without text, open a small split on the steering draft
			at the end of the same session buffer. With text,
			queue it for the active run (|straps-steering|). With
			no active run, add it to the trailing user block and
			send it with |:StrapsSend|.

Commands that act on a session (|:StrapsSend|, |:StrapsSteer|, |:StrapsStop|,
|:StrapsPermission|, |:StrapsContinue|, |:StrapsCompact|, |:StrapsRename|,
|:StrapsAuto|) act on the current buffer when it is a session, else on the
sole distinct session buffer visible in the current tab. Otherwise they warn
and do nothing.
|:StrapsModel|, |:StrapsEffort| and |:StrapsProvider| use the same session
resolution, and make a global pick when no session resolves.

							*:StrapsStop*
:StrapsStop		Request cancellation of the active run. The run
			notices between turns and between tool calls, kills an
			in-flight request or `bash` process, and ends with a
			user-role `[straps] run cancelled (:StrapsStop)` note
			appended to the transcript. To pick the work back up,
			see |:StrapsContinue|.

							*:StrapsPermission*
:StrapsPermission	Open the session's pending permission review. Run it
			from the session or from another window when exactly
			one session is visible in the current tab. Choose an
			outcome in the review itself, or use |:StrapsStop| to
			cancel the waiting run.
							*:StrapsInspect*
:StrapsInspect		Open the pending file edit's unified diff from its
			transcript. The split adjoins the transcript and leaves
			its focus and cursor in place. Closing the diff leaves
			approval pending. Use |:StrapsPermission| to decide.
			Only the default confirmation hook for write_file,
			edit_file and patch_file supports this action.
							*:StrapsContinue*
:StrapsContinue [{text}]
			Continue a run that was stopped (|:StrapsStop|) or
			interrupted, in the current session. There is no run
			state to restore — the buffer IS the state — so this
			just appends a user block ({text}, or a generic
			"continue where you left off") and sends: the stopped
			transcript is already well-formed. The
			continued run gets a fresh |straps-config| `max_turns`
			budget, a fresh stall counter and fresh blank-turn
			nudges; the conversation itself is unaffected. Errors
			if a run is already active — |:StrapsStop| it first, or
			|:StrapsSteer| it instead. Distinct from
			|:StrapsResume|, which reopens a saved transcript from
			disk.

									*straps-contextual-authorization*
Contextual authorization is experimental and disabled by default. Configure
straps_classifier.setup with an explicit contextual options table after core
setup and before sessions/guard freeze; see |straps-classifier-contextual| and
the classifier README for disclosure/route/limits/threshold configuration.
Restart to change mode/configuration. Contextual setup bypasses only the legacy
classifier chain. Ordinary confirmation, other guards, and child ceilings
remain. Auto grants do not establish task authority.

Core keeps private instruction events outside the editable transcript. Trusted
human submission, steering, and full bound question answers revise authority
before work queues run. Standing snapshots and private prompt construction
receipts bind adoption to exact sources and the stored prompt. Transcript
edits, user-role labels, notices, summaries, and copied text grant nothing.
Changed standing instructions or prompt definitions require renewed adoption.
Legacy/resumed sessions, piped data, and copied fork prompts need adoption,
which can regenerate the prompt. Continue without text retains the task;
supplied text revises it. Stop cancels run tickets and retains task identity and
rejected-family suppression. Question answers record selected-option identity or
free-text origin; typing an option label remains free text.

Use |:StrapsAdopt| to review task text/standing sources; |:StrapsTaskReset|
invalidates the task and pending decisions. |:StrapsAuthorization| inspects a
known decision ID. With !, it requests a fresh review through the human
scheduler. Exact-call consent binds input, tool definition, task revisions and
target assumptions, and consumes once at execution. Changed input or context
invalidates approval. Rejected decision families remain suppressed until human
reopening. A fresh review does not invoke the original denied closure or retry
an unknown execution outcome. Execution-started receipts retain metadata only;
retained denied decisions support exact-call inspection and fresh reopening.
Classifier consent cannot bypass other guards
or enlarge readonly/allow ceilings. Children receive only validated explicit
subset delegation; copied conversation and archive access confer no authority.
In contextual mode, generic human :StrapsFork/fn.fork calls are unavailable:
they lack a trusted exact invocation. Agent fork without delegation creates an
inactive copy requiring human adoption before starting. Explicit fork delegation
is rejected because the copied prompt has no valid private construction receipt.

An adopted session can remain pending without a synthesized task specification.
Automatic authorization stays denied when disclosure, synthesis, assessment, or
integration is unavailable. Human reopening can approve the displayed exact call
despite that unavailability or displayed classifier objections. The approval does
not synthesize or activate a task. Independent guards, ordinary confirmation,
readonly/allow ceilings, fresh call and target checks, and consumption once at
execution still apply.

Missing disclosure, failed synthesis/assessment, and unavailable dependencies
deny automatic authorization as unassessed, without repeated consent prompts. Current
bootstrap call inputs and observed evidence have unknown sensitivity;
validation refuses unknown even if an allowed-class map names it. Production
per-call provider requests remain blocked pending approved sensitivity and
disclosure policy and implementation. Arbitrary inputs are not certified free
of secrets. The contextual adapter supports the default OpenAI endpoint with
API-key or existing OAuth credentials; other providers, custom routes, and
Codex remain unavailable.

Contextual ceilings trust private classification of exact shipped definition
identities. Public capability metadata and fn.capability replacements do not grant
trusted categories to custom tools; exact-definition assessment and independent
ceilings remain required.

Target revalidation cannot eliminate filesystem races after a check or enforce
shell/executable behavior. Same-process Lua is no operating-system boundary.
Disclosure, numeric calibration/acceptance, default enablement, and locked-core
compatibility remain parked. Offline tests do not establish completed
integration or live calibration.

			*:StrapsAdopt*
:StrapsAdopt [{text}]
			In contextual mode, review and adopt exact task text and
			standing instructions. Without {text}, use the trailing
			request, or retained events when no request is present.
			Adoption can regenerate the prompt. See
			|straps-contextual-authorization|.

			*:StrapsAuthorization*
:StrapsAuthorization[!] {id}
			In contextual mode, inspect the named decision for this
			session. With !, request a fresh authorization review
			through the human scheduler. This does not execute the
			original denied closure or repeat an unknown outcome.

			*:StrapsTaskReset*
:StrapsTaskReset		In contextual mode, invalidate the authorization task
			and pending decisions. This does not erase the transcript.

			*:StrapsLogin*
:StrapsLogin [{provider} [key]]
			Store a key for {provider} (default: the current
			buffer's provider; for openai the bare form is the
			ChatGPT sign-in below). anthropic and llamacpp prompt
			for the key (not echoed) with or without `key` and
			write it with |fn.api_key_store|. The key is never an
			argument; any other extra argument is rejected and its
			line removed from command history (the |quote_:|
			register keeps it until the next command line; it is
			not written to ShaDa). With a key already stored, the
			prompt says that it replaces the stored key. The
			success message names any set key variable that the
			stored key overrides.
:StrapsLogin openai [{url}]
			Sign in with ChatGPT for the OpenAI provider. Without
			{url} it opens the ChatGPT sign-in page and prints its
			URL. After sign-in the browser fails to load a
			http://127.0.0.1:1455/auth/callback?... page; copy that
			full URL from the address bar and run
			`:StrapsLogin openai {url}`. The login is stored in
			$XDG_CONFIG_HOME/straps/openai_oauth.json (mode 600),
			refreshed automatically, and wins over the stored key
			and $OPENAI_API_KEY. Completing the login deletes a
			stored OpenAI API key through |fn.api_key_store| and
			the success message says so; a symlinked key file is
			left in place and the ChatGPT login takes precedence
			over it. Refused when `openai_base_url` is not
			https://api.openai.com. See |fn.openai_api_key|.
:StrapsLogin openai codex
			Sign in the way the Codex CLI does, for accounts or
			models the ChatGPT sign-in does not serve. It opens
			the sign-in page; after sign-in the browser fails to
			load http://localhost:1455/auth/callback?...; run
			`:StrapsLogin openai {url}` with that URL. A running
			Codex CLI login listens on port 1455 and takes the
			code; stop it first. The login is stored in
			$XDG_CONFIG_HOME/straps/openai_codex.json (mode 600)
			and requests go to
			https://chatgpt.com/backend-api/codex/responses.
			Completing it deletes the stored key and the ChatGPT
			login. Pick a Codex model with |:StrapsModel|. Refused
			when `openai_base_url` is not https://api.openai.com.
:StrapsLogin openai key
			Prompt for an OpenAI API key and store it, then sign
			out of ChatGPT and the Codex login (cancelling a
			pending login). A rejected key changes nothing; if a
			sign-out fails the key stays stored and that login
			still wins.

							*:StrapsLogout*
:StrapsLogout [{provider}]
			Delete {provider}'s stored key; for openai also cancel
			a pending ChatGPT or Codex login and delete the stored
			ones. Names any variable the default key fn would
			still read. Without {provider} it asks first.

							*:StrapsAuto*
:StrapsAuto [off|all|{cats}]
			Grant capability categories to the current session so the
			matching tool calls run without a confirm prompt (session
			buffers only). `:StrapsAuto edit,exec` grants those
			categories; `all` grants every grantable one. With Snacks available, no argument opens a
			multi-select picker with current grants selected. Tab
			toggles categories; Enter replaces the category grants
			with the selection (empty clears them); Esc cancels.
			Without Snacks, no argument reports the current grants.
			`off` clears every category grant (leaving editdir: and
			per-tool grants intact). Completion offers `off`, `all`
			and the grantable categories. See |straps-auto| and |fn.capability|.

							*:StrapsCompact*
:StrapsCompact		Mechanically compact the current transcript — shrink
			old tool_use/tool_result contents in place — and
			notify the summary. See |fn.compact|.

							*:StrapsEdit*
:StrapsEdit {name}	Open registry entry {name} (e.g. `fn.render`,
			`hook.confirm`, `tool.bash`) as an executable Lua
			buffer in a split (|<mods>| as for |:Straps|; a
			window already showing it gets focus). Writing the
			buffer (|:w|) re-executes it, redefining the entry.
			Completion lists every entry. See |straps-registry|.

							*:StrapsRegistry*
:StrapsRegistry		Open a scratch listing of every registry entry in a
			split (|<mods>| as for |:Straps|); <CR> on a line
			opens that entry in the listing's window.

							*:StrapsHelp*
:StrapsHelp [tag]	Open |:help| for straps (default tag `straps`, or
				a supplied straps help tag such as `straps-tools`).
				Completion lists every tag starting with
				`straps` in the help tags files.

							*:StrapsEval*
:StrapsEval		Execute the current buffer as Lua.

							*:StrapsAgents* *straps-agents*
:StrapsAgents		Open the agent dashboard (straps://agents): loaded
			session trees and a saved-transcript archive with
			native folds, search, and selected-agent details.
			The winbar shows management keys; config
			`agents_winbar = false` puts the legend in the buffer.
			<CR> replaces the dashboard in its window, so
			<C-o>/<C-i> navigate back and forward. Refresh retains
			selection and folds. Takes the same |<mods>| as
			|:Straps| (:vertical StrapsAgents for a vsplit).
			See the dashboard keys below and |straps-subagents|.

							*:StrapsProvider*
:StrapsProvider		Pick the backend: anthropic, openai or llamacpp. On a
			resolved session it sets b:straps_provider for that
			session only; with no target it sets config `provider` and
			persists the choice to ~/.config/straps/provider
			(|fn.provider_pref|). Run |:StrapsModel| after it to
			pick that provider's model. A session keeps the
			provider and model of its first successful request,
			saved in the transcript's .meta file, so a global pick
			affects only sessions that have not made a request.

							*:StrapsModel*
:StrapsModel		Pick the provider-specific model for the current session
			(or the only visible session in the tab; global default
			when no session resolves). Does live
			discovery via |fn.list_models| and merges the
			provider's catalog over `models`, `openai_models` or
			`llamacpp_models`. A session pick is saved in the
			transcript's .meta file and restored on resume. A
			global pick persists per provider to
			~/.config/straps/model_<provider> (|fn.model_pref|);
			a model key set in setup{} wins over it.

							*:StrapsEffort*
:StrapsEffort		Pick the extended-thinking effort (off/low/medium/high
			by default) for the resolved session or globally
			when no session resolves.

4. THE SESSION BUFFER					*straps-session*

A session is a single ordinary buffer — there is no separate compose window.
You type your message directly under the trailing `%%[straps:user]%%` marker,
the same buffer the loop reads and appends to. Editing earlier history before
you send is intentional, not an accident.

Sessions are durable: the buffer is backed by a real file under
|straps-config| `session_dir` (`*.straps`), persisted at every block boundary,
so it survives a restart and |:StrapsResume| just reopens it.

Because persistence happens at block boundaries, a session whose Neovim died
while a tool was still running is saved with a `tool_use` block that never got
its `tool_result` — a shape the API rejects. |:StrapsResume| repairs that on
open: each unfinished tool call gets an error result ("run interrupted before
this tool finished") and the trailing user block is restored, so the resumed
session can be sent. |:StrapsContinue| then picks the work back up. Two things
are deliberately left alone: a session that still has a run in flight (a
running tool is indistinguishable from an interrupted one, so repairing it
would report a false failure), and a transcript whose tool blocks were
hand-edited into an inconsistent state — that still fails loudly when sent.

Buffer-local mappings (normal mode), set in session buffers and in any
hand-opened `*.straps` file:
	<CR>	Send or open the steering split (|:StrapsSend|).
	gf	Open the `path:line[:col]` reference under the cursor; any
		other text falls back to the built-in |gf|, and its error
		is shown as a warning.
	]]	Jump to the next conversation turn ([count] turns).
	[[	Jump to the previous conversation turn ([count] turns).
	gO	List the turns in the window's |location-list|.
	gE	Jump to the original tool-result quote when the cursor is on
		a claim and the session winbar shows the evidence hint.
		Use |CTRL-O| to return. Evidence links are buffer-local and
		do not persist when you reopen or fork the session.
Changing 'filetype' away from straps removes these mappings and restores the
fold and conceal options.

Transcript grammar. Blocks are marker lines `%%[straps:KIND]%%` (with compact
JSON attrs for tool blocks) followed by content; KIND is one of
`system user assistant tool_use tool_result`. `fn.render` (|straps-fn|) draws a
display-only layer of conceal + extmarks + folds over the raw markers; nothing
mutates the buffer text. `:set conceallevel=0` reveals the raw markers, and
|straps-config| `render = false` turns the whole layer off.

Closed tool folds show a muted chevron and tool name, a target when known,
and status or count from result marker metadata. `failed` uses
`StrapsToolError`. The fold does not infer metadata from output.
An override of |fn.tool_display| formats the label and target text.
Open a tool fold with |zo| to see a muted `╭ │ ╰` bracket to the left of its
output. The bracket uses `StrapsCardBorder` and does not enter yanked text.
Prose and tool inputs have no bracket prefix.

The `── since you left ──` divider marks the first line affected by output
while the transcript is unfocused, even when a split still shows it. Draft
edits do not set the divider. Move the cursor or scroll the top of the view
past it to clear it in all views. `render = false` disables the divider.

							*straps-steering*
Steering. A message sent while a run is active is queued (not started as a new
run) and drained into the transcript at the next turn boundary, so the model
acts on it mid-flight. |:StrapsSteer| without arguments opens a split below
its originating window. Both views use the same session buffer. Draft text
stays out of model requests until submitted. Use `:close` to keep the draft
and `:StrapsSteer` to reopen it. Normal-mode <CR> or |:StrapsSend| in the
split submits a nonblank draft and returns to the original view. If the run
has ended, the text moves to the trailing user block for a separate send.

The harness steers through |fn.session_notify|: a subagent completion notice
reaches a busy parent this way, without the
"steering queued" toast a message you typed produces. Each queued entry records
its source: `user` (you), `harness` (a notice), or `agent` (|send_message|).
Any queued entry ends a `spawn_wait` early, so a waiting agent reads it at
once. Steering you send, and any run you start, re-arms |watch_agent| wakes
for that session.

Progress. While a run is active a virtual-text indicator on the last line
shows the phase, elapsed time, stream liveness and the stop/steer hints. The
policy is the redefinable |hook.on_progress|.

Winbar. Session windows get a window-local winbar showing the effective model,
effort and run status, plus live token usage once the first response arrives —
the context fill (e.g. 47.0k/200k (24%)) and cache hit rate, from
`ui.usage_status()`. Disable with |straps-config| `session_winbar = false`.
Buffer/window leave removes only the Straps expression and restores the prior
local value. Returning to the session reinstalls the expression. Global values
and user replacements remain unchanged.

The session winbar shows `◆ waiting` when a permission request needs a decision.

Own components. `ui.session_info(bufnr)` returns the session's RESOLVED state
(provider, model, model_label, effort, overridden, status, parent, usage,
context_used, context, context_pct, cache_pct), or nil when bufnr is not a
session buffer; bufnr defaults to the current buffer. The buffer variables are
raw — an unset override says nothing about the effective value — so build
statusline/winbar components on session_info rather than on b:straps_model.
`ui.session_status()`, `ui.usage_status()` and `ui.session_winbar()` all take
the same optional bufnr, and `ui.human_tokens(n)` formats a token count.
Note a GLOBAL tabline cannot resolve the session implicitly: %{} there (and
bufnr() inside it) evaluates in the current window's context. Pass a bufnr
from a Lua component framework, or use `ui.agents_status()`.

5. CONFIGURATION					*straps-config*

Pass these to |straps.setup()|. Defaults shown.

						*straps-config-model*
model			(string|nil) nil. The Anthropic request model. nil uses

6. THE REGISTRY						*straps-registry*

The registry is the heart of the plugin. Every tool, hook and core function is
an entry: a Lua source string, compiled on define, looked up by name at every
call site. Names are namespaced `tool.<name>`, `hook.<name>`, `fn.<name>`,
`skill.<name>`.

Scoping. `registry.define` targets the active scope, or the global registry
when no scope is active. The agent's `registry_define` tool defaults to its
active session; its explicit scopes are `session` and `global`. Session entries
shadow globals. A child inherits its parent's shadows, then applies its own;
parent sessions do not see child entries. Scoped entries vanish when their
session closes. By default, `registry.remove` removes the nearest entry in the
active scope chain, then the global entry when no scoped entry exists. Its Lua
API can target `global` or start from a numeric buffer scope.

Versioning. Redefining an entry bumps its `version`; the first-define `seq` is
preserved so the API tool array stays append-only (prompt-cache stable). The
previous source is not retained — there is no built-in rollback; keep your own
copy, or re-render with |:StrapsEdit|.

Persistence. A trusted `.straps.lua` at the project root is loaded
automatically at session start (direnv-style sha256 trust; you are prompted,
defaulting to No, on new or changed content). It is plain Lua:
`registry.define{...}` calls, which is exactly what `registry.render(name)`
emits — so appending a |:StrapsEdit| buffer's content to `.straps.lua` keeps
an entry across restarts. See |straps-health| for the trust state.

Inspect and edit from Lua:
>lua
	local reg = require("straps").registry
	reg.names("tool")          -- list tool names
	print(reg.render("fn.render"))  -- the entry as executable Lua
<
Or from the agent's own tools: `registry_list`, `registry_get`,
`registry_define` (|straps-tools|).

						*registry.get* *registry.bind*
What you get back. `registry.get(name)` returns a read-only COPY of the
entry's public fields (`name, kind, doc, input_schema, capability, source,
version, seq, scope`) — never the compiled function, and never the stored
table, so writes to it change nothing. To chain onto a previous definition
(the |fn.capability| example under |straps-auto|), capture it with
`registry.bind(name)`, which returns the compiled function resolved now.
`bind` refuses `tool.*`: tools run only through `registry.call`, which passes
the guard chain (|hook.guard|). Entry storage is private to the module;
`registry.entries` and `registry.scopes` do not exist. Grants live in the
registry too (`registry.grant`, `registry.granted`, `registry.clear_grants`;
see |straps-auto|). A tool-name grant is keyed `<name>@v<version>`, plus
`@<bufnr>` for a session-scoped entry (`registry.tool_grant_key(name)`), so a
session shadow or a redefinition of that tool no longer matches the grant:
the default |hook.confirm| prompts again, a subagent's gate denies. A scope's
parent is fixed when the scope is created.

7. TOOLS						*straps-tools*

Tools are what the agent calls. Every one is a registry entry (|:StrapsEdit
tool.NAME|) and every write goes through |hook.confirm|. The defaults:

File & shell:
	read_file, write_file, edit_file, patch_file, path_info, tree,
	fetch_url, glob, grep, bash, run_in_terminal, show_terminal, run_quickfix,
	move_file(s), delete_file(s)

Editor-native (tree-sitter / LSP; with no server or parser the call fails
with "<tool>: no LSP client ..." and the loop marks it an error):
	diagnostics, diagnostic_at, diagnostic_next, fix_diagnostic,
	lsp_status,
	declaration, definition, type_definition, implementation,
	references, hover, tree_sitter_status, node_at, read_node,
	symbols,
	read_symbol, workspace_symbols, code_action, rename_symbol,
	format, bulk_replace

Presentation & interaction:
	show_user, show_diff, show_buffer, set_findings, context, ask_user,
	help_search, undo_edit

Self-extension & orchestration:
	registry_list, registry_get, registry_define, skill, eval_lua,
	spawn, spawn_wait (|straps-subagents|), agents
	(|straps-multiplayer|), send_message (|straps-send-message-tool|),
	watch_agent, unwatch_agent (|straps-watch-agent-tool|),
	transcript_excise

`transcript_excise` is context surgery: with no arguments it lists the
transcript's blocks; with `blocks`/`range` and a required `note` it replaces
those blocks' contents with a one-line `[excised: ...]` receipt, so a finished
side quest stops being replayed in later requests. It cannot delete a block,
cannot write text other than the receipt, and never touches the system block or
the turn in flight. `session` targets a subagent's transcript instead.

`ask_user` renders the question and its numbered options as virtual lines
under the last assistant block of the session transcript, so the agent's
reasoning stays visible above the question. While it is up, the session
buffer takes over these normal-mode keys: `j`/`k`/<Down>/<Up> move, <CR>
chooses, `1`-`9` choose by number, `o` types a free-text answer, <Esc>
dismisses. Any prior buffer-local map on those keys (the session's own <CR>
send/steer map included) is restored when the question is answered. Options
with a preview share one split beside the session window, swapped as the
selection moves; `content` opens a bottom scratch split. Focus returns to
the window the user was in before the question.

`bash` runs `bash -lc` in Neovim's current directory (|getcwd()|), so a
leading `cd <project> &&` is unnecessary. It refuses read/search/list
commands (cat/head/tail/sed -n/wc, grep/rg, ls/find/fd, stat/file) run bare
or piped only into head/tail/wc/sort/uniq/cut/tr, and bare curl/wget of a URL,
also behind one leading `cd <dir> &&`, and names the native tool to use
instead. A redirect,
`;`, `&&`, `||`, `$(`, backtick, `sudo` or any other pipeline stage lets the
command run. From the second identical command (12+ characters) in a
session, the result ends with a note suggesting a `registry_define`d tool.

`run_in_terminal` runs its command in a |terminal| buffer that has no window,
so agents running terminals do not change your layout. The result names the
buffer. Each session keeps only its most recent terminal buffer; the next run
wipes the previous one, or, if a window shows it, wipes it when that window
closes. `show_terminal` opens a
terminal buffer (default: the session's last one) in a 15-line split at the
bottom without moving focus, and reuses that split on later calls.
`run_in_terminal` with `show=true` opens the split when the job starts, so
the output can be watched live. To open one yourself: `:sbuffer {N}` with the
buffer number from the tool result.
Writes (write_file/edit_file and the LSP refactors) apply THROUGH the file's
buffer, so they land in the file's native undo tree — the user reverts with
|u|, |:earlier| or undotree, and `undo_edit` can revert a specific past edit.

Run |:StrapsRegistry| for the live list with one-line docs, or `registry_list`
from the agent side.

8. HOOKS						*straps-hooks*

Hooks are the "always do X" seams. Each is a registry entry you can redefine
(|:StrapsEdit hook.NAME|). Redefining "always"-shaped behavior into a hook
beats remembering to repeat it.

							*straps-hooks-fanout*
Fan-out. Some hooks are broadcast to MANY subscribers, not just the one entry
named `hook.NAME`. A subscriber registers itself as `hook.NAME.<suffix>` (e.g.
`hook.after_write.mylinter`). `registry.hook_entries(name)` returns the entry
named exactly `name` PLUS every `hook.name.<suffix>` entry, over the merged
active scope, sorted by registration order (`seq` ascending — the builtin
default first). `registry.call_hooks(name, ...)` runs each with `pcall` so one
broken subscriber cannot stop the others, and returns two tables: `results`
(the non-nil returns, in order) and `errors` (one `{ name, err }` per
subscriber that raised). Add a subscriber with `registry_define` (kind "hook",
name `hook.NAME.<suffix>`); no need to redefine the default.

The fanned-out hooks: |hook.after_write| (all string results appended to the
tool result; a raising subscriber becomes a `[hook <name> error: ...]` line),
and the loop's |hook.on_run_start| / |hook.on_run_end| / |hook.on_turn_start|
/ |hook.before_tool|. |hook.after_tool| is fanned out as a FOLD: each
subscriber gets the CURRENT result and any non-nil return replaces it for the
next one, in registration order. |hook.guard| is a fold with the opposite error
policy: every guard runs and a raising guard BLOCKS. NOT fanned out (single
entry, called directly): |hook.confirm|, |hook.on_progress|, and
`hook.on_define`.
						*hook.confirm*
hook.confirm(name, input, ctx, call_id?) -> allowed, reason, source
		A refusal with source `"hook"` is a policy veto and reads
		`blocked by hook.confirm: <reason>`; any other refusal
		reads `user denied: <reason>`. The permission gate, called for every tool the model requests,
		after the before-guards (|hook.guard|). Default:
		auto-allow the read-only tools; silently allow any call
		whose |fn.capability| category has been granted (a
		`cap:<category>` key in the session's grant set, written by
		|:StrapsAuto| or a subagent `allow`); otherwise prompt
		(Yes / No / Always this tool / for edits, Always in <dir>
		/ Always all edits). For pending file edits, open the diff
		with |:StrapsInspect| and decide with |:StrapsPermission|.
		"Always all edits" (`editfiles:*`) covers every |fn.capability|
		`edit` call, including bulk_replace, rename_symbol, format,
		move_file(s), undo_edit and code_action with an index; those
		tools also offer it. delete_file/delete_files offer only
		Yes / No and warn that deletion is not undo-reversible.
		registry_define also offers no "Always this tool" option
		and ignores tool-name grants. Grants persist via
		`registry.grant`; "Always this tool" stores
		`registry.tool_grant_key(name)` (`<name>@v<version>[@<bufnr>]`).
		A redefinition or session shadow invalidates that name grant;
		a category grant may still permit the revised tool.
		Never loosen this on the agent's initiative. See
		|straps-auto|. In a batch, every call of a segment is
		confirmed before the first one runs; for a second edit to the
		same file, `ctx.batch_preview(path)` returns the file as the
		earlier edits of the segment leave it, and the diff preview
		is computed against that text.

						*hook.guard* *straps-guards*
hook.guard.<suffix>(op, ...) -> verdict, reason
		The policy chain the agent cannot alter. Install guards in
		`stdpath("config")/straps/init.lua` (or your init.lua after
		`setup()`); the chain FREEZES when that file has loaded and
		at the first run — after that nothing (you, the agent, a
		`.straps.lua`) defines, redefines or removes a guard until
		Neovim restarts. Guards are global-only. None ship.

		Every guard is called for every op, in registration order,
		with a fixed argument list per op: >
		  ("before", name, input, ctx, info)
		  ("after",  name, input, result, ok, ctx, info)
		  ("define", spec, opts, info)
		  ("remove", name, opts, info)
<		`info` is `{ active = bufnr|nil, executing = tool|nil,
		frozen = bool }`. Return `false, reason` to BLOCK: the tool
		does not run (before), the model sees
		`blocked by <guard>: <reason>` as an error result, and
		|hook.confirm| is not consulted; for define/remove the call
		raises. For "after", a string return REPLACES the result the
		model sees (runs last, after |hook.after_tool|, on the
		truncated result). Anything else passes — `true` never skips
		the confirm prompt. A guard that raises blocks. `ctx` is nil
		for define/remove and for tools run directly via
		`registry.call`; on the loop path a before/after guard may
		`ctx.await` (a model-based classifier is a curl).

		Scope guards by `op` and name. A guard blocking every
		`define` during a run breaks `spawn`, which defines the
		child's confirm shadow. Each guard call logs a
		`{ ev = "guard", op, name, guard, verdict, ms }` event to
		|fn.log|. Example — refuse writes to the straps config dir: >lua
		require("straps.registry").define{
		  name = "hook.guard.config_dir", kind = "hook",
		  doc = "no agent writes under stdpath('config')/straps",
		  source = [==[
		    local dir = vim.fn.stdpath("config") .. "/straps/"
		    return function(op, name, input)
		      if op ~= "before" then return end
		      local p = type(input) == "table" and input.path
		      if type(p) == "string"
		        and vim.fn.fnamemodify(p, ":p"):sub(1, #dir) == dir then
		        return false, "straps config dir is off limits"
		      end
		    end
		  ]==],
		}
<		Ceiling. A silently granted `lua` or `exec` category, or a
		hash-trusted `.straps.lua`, is full-privilege Lua in the same
		process: `debug.*`, `ffi`, `package.loaded`, `load()` of an
		entry's `source`, `nvim --server $NVIM` from bash, and editing
		the session buffer all reach past the chain. Straps does not
		harden against those; a guard classifying `eval_lua`/`bash`
		input is where such attempts are visible.

						*hook.after_write*
hook.after_write(path, ctx) -> string|nil
		Called after write_file / edit_file / patch_file. If it returns a
		string it is appended to the tool result. The default feeds the
		editor's own LSP back to the agent: it waits briefly for the language
		server to re-lint the just-written file, then returns its
		ERROR/WARN diagnostics, so the agent sees breakage it caused
		without being asked. No client on the file, or no new
		diagnostics, appends nothing. Turn off with
		|straps-config| `after_write_diagnostics = false`, or redefine
		it to run an external linter instead. Fanned out
		(|straps-hooks-fanout|): this default plus every
		`hook.after_write.<suffix>` subscriber runs, and all their string
		results are appended in registration order — add a linter without
		replacing the diagnostics default.
		Inside a batch the loop sets `ctx.defer_diagnostics(path)`: the

						*straps-context-management*
OPT-IN CONTEXT MANAGEMENT~

`context_management = { enabled = false }` leaves the legacy compaction path
active. Pending retrieved results remain protected even when disabled.
Enable it with `enabled = true` and choose `mode = "mechanical"` or
`mode = "summary"`. Override settings per session with
`b:straps_context_management`. |:StrapsCompact| continues to call |fn.compact|.

The default budget counter estimates the serialized provider request with
`bytes_per_token = 3`, `safety_margin = 1.3`, and 64 extra tokens. The estimate
includes tools and system text and is not an exact token count or a guarantee
of provider acceptance. Set `input_limit` when model metadata is unknown or a
custom provider is installed. `context_limit` describes a combined window and
requires an effective `output_reserve`. The default `reserve_tokens = 4096`
leaves room for protected archive evidence.

Controls inside the `context_management` table:
  trigger           0.85: pressure fraction of the available input allowance.
  target            0.7: required post-compaction fraction.
  keep_turns        2: recent assistant turns to preserve.
  minimum_savings   128: minimum estimated tokens recovered.
  idle_compaction   false: enable compaction after idle eligibility.
  idle_seconds      300: idle interval when idle compaction is enabled.
  retry             true explicitly retries a failed summary source/config.
  summary           Bounded generation settings; see below.

Mechanical mode archives old eligible tool results and replaces them with
`[straps-context:<id>]` receipts. It preserves user and assistant prose.
Summary mode may replace older completed assistant/tool intervals with
attributed summaries between preserved original user/system blocks. Summary
requests have no tools. Generation makes provider requests; structural tests
do not establish fidelity. Codex per-request output-cap support is not
established; the summary integration refuses that route without probing it.
The standalone tests/context_quality_eval.lua runner has offline self-test and
dry-run modes and a separately gated live mode. Offline modes do not measure
model quality. See the README for the live gate, runfile, transport logging,
artifact sanitization limits, and usage limitations. Summary compaction uses one shared bounded attempt across
selected spans, recounts aggregate replacements, and stops at the target.
No span is adopted when a required later span fails. Enabled context management
permits one retry after a typed pre-output HTTP 400 context-overflow rejection.
Core captures live/disk source, protections, effective configuration, tools and
model note before dispatch. Recovery forces recount/reduction despite the soft
trigger, requires minimum savings and a fitting target, and shares the normal
boundary's summary attempt allowance. It recaptures pending results and retries
in the same turn without rerunning tools or adding an assistant placeholder.
Only the exact unchanged empty placeholder is excluded from retained-turn counts.
Cancellation, emitted events including queued streaming output, edits, changed
configuration/protection, ordinary errors, insufficient reduction and a second
rejection prevent another retry. Failed recovery retains pending evidence.

Summary settings default to `max_input_tokens = 8192`,
`max_output_tokens = 1024`, `max_total_tokens = 65536`, `max_calls = 32`,
`max_depth = 4`, and `max_retries = 0`. The summary module's fallback accounting
uses serialized byte counts as conservative token estimates. Bounded splitting
and merges retain original source references and child records. Exhausted
budgets or incomplete responses leave the transcript unchanged.

Archives and trusted grants persist in the private `.context-archive` subtree
under `session_dir`. Ephemeral transcripts also require persistent archives;
the archives do not make ephemeral transcripts resumable. Failed archive
persistence prevents adoption. Checked transcript persistence uses a native
nonforced noautocmd write, verifies saved bytes, and synchronizes the file and
parent directory. The writer does not provide controlled temporary-file/rename
atomicity. A failure after the native write begins reports an ambiguous disk
outcome. Compaction attempts live rollback; pending-result transactions restore
live text only when unchanged disk and source identity remain verified.
Archives have no automatic deletion. Grant updates use a per-session exclusive
lock and merge current durable grants. A busy lock fails without waiting. After
a crashed writer, confirm that no writer remains before removing its reported
`.lock` file; never remove a lock held by another process.
Fork integration inherits only
trusted references within the copied transcript cutoff; pasted IDs grant no
access. File-backed archive grants use the session's absolute pathname. Renaming
or using `:saveas` on a compacted transcript does not migrate those grants;
retain the original session path for recovery. Use a supported fork to copy
archive access to another session.

Lua preview/apply calls require the target session's registry scope and a
scheduler-owned asynchronous context across yields. Use the Ex controls for
interactive work; passing a buffer number alone does not install its scope.

Lua controls: `require("straps.context_management").pin(bufnr, first, last)`
protects finite integer block endpoints; `unpin(bufnr)` clears pins. Pins capture
the exact marker-inclusive prefix through the last pinned block. Appends preserve
disjoint pins, including a final block's appended blank separator. Changed captured
prefixes or boundaries conservatively prevent compaction until unpinning.
`preview(bufnr, ctx, opts)` returns detached data without adoption or executable
functions. Summary preview returns `needs_generation = true` unless
`opts.generate = true`; that flag permits potentially paid generation. Supply
continuation inputs through `opts.tools` and `opts.note`; preview captures copies
along with source/disk identity and effective configuration before generation.
`apply(bufnr, ctx, report, tools?, note?)` applies only the exact unchanged report
with the same buffer/context. Every attempt consumes the report before validation
or replaceable work. Apply rejects fabricated, copied, modified, stale, and used
reports. Omitted tools/note use captured copies; supplied values must equal those
copies and remain unchanged through accounting and prewrite checks. Apply rechecks
source, disk, configuration, protections, cancellation, and budget. Applying a
generated report never generates again, even when another generation is suppressed.
Closing or replacing a generated preview discards its candidate but retains the
source/configuration generation-suppression key. Preparing it again requires an
explicit `context_management.retry = true` override or a relevant source/configuration
change; retry can spend tokens again. Apply the existing preview before closing it.
Refusal/failure may retain orphan archives and creator grants for evidence retrieval;
these grants confer no instruction authority. `b:straps_context_compaction` records
status/reason, before/after count reports, archives, first_block/last_block, and
earliest_line.

:StrapsContextPreview[!] [summary]                  *:StrapsContextPreview*
Requires enabled context management and uses its configured mode. The optional
summary argument requires summary mode. Without ! no summary provider request
runs; ! permits bounded generation. A read-only nofile split shows the proposed
transcript, count source, uncertainty, budget, interval, earliest changed line,
and unknown accounting/cache values.

:StrapsContextApply                               *:StrapsContextApply*
Consumes the exact private per-session preview without regeneration. Current
continuation tools and model note must still equal the captured inputs.

:[range]StrapsContextPin                          *:StrapsContextPin*
Pins every transcript block intersecting the selected line range, including
marker lines. Select the range in the transcript buffer.

:StrapsContextUnpin                               *:StrapsContextUnpin*
Clears every pin for the resolved session. Commands use the current or sole
visible session and never enable context management. Context operations reserve
the session against runs and ordinary human operations until async completion.
Closing the preview, wiping the session, or :StrapsStop cancels pending work.
b:straps_context_control records status and reasons.
Only explicit `fallback = "mechanical"` permits fallback after typed generation
or budget failure or aggregate fit failure. Core revalidates source, protections,
configuration and cancellation, recomputes original mechanical eligibility, and
invokes the same captured policy in mechanical mode. Fallback spends no further
summary requests. Invalid policy, stale source, cancellation, transaction and
archive failures never enable fallback. Usage observations can calibrate later
append-only requests; see |fn.context_budget|.

                                                *fn.context_plan*
fn.context_plan(input, ctx) -> proposal
The late-bound registry interface accepts detached core-eligible proposal data.
Core validates selections before generation or mutation. Input fields:
  version = 1
  snapshot_id = opaque snapshot identity
  reason = "pressure" | "idle" | "overflow" | "explicit"
  mode = "mechanical" | "summary"
  before = {tokens, limit, source, exact}
  target_tokens = desired continuation token limit
  eligible = {{index, first_block, last_block, mode, sources?}, ...}
Each interval's index equals its array position. The default returns
{version = 1, snapshot_id = input.snapshot_id, selections = {indices...}}
in eligible order without changing history or generating summaries. Custom
policies return the same proposal schema. An explicit adapter override is: >lua
  require("straps.registry").define({
    name = "fn.context_plan", kind = "fn", source = [[
      return function(input, ctx)
        return require("straps.registry").call("fn.compact", nil, {context_plan = input})
      end
    ]],
  })
<
Only a custom fn.compact that handles `if opts and opts.context_plan then ... end`
and returns the proposal schema from that branch supports this adapter. Existing
string-returning overrides remain manual-only. Default fn.compact has no proposal
branch. Core captures the policy function and policy/adapter source identities.
Results require version 1, the exact snapshot and a dense ordered array of unique
known eligible indices. Input mutation, overlap and mode mismatch refuse.
Core owns eligibility and protections; policies cannot expand the eligible set.

Overflow errors use a trusted provider protocol: >lua
  error({kind = "context_overflow", rejected = true, response_started = false,
    provider = "...", route = "...", status = 400, code = "...", message = "..."}, 0)
<
Built-in backends classify complete successful-transport HTTP rejection bodies
before output: OpenAI context_length_exceeded or Anthropic's exact
invalid_request_error prompt-too-long shape. Custom same-process providers may
raise the same table. Raw-field and emitted-event checks supply no unforgeable
classifier proof. Failed recovery reports its current reduction/validation
error; ordinary and second provider failures report their provider error.
Compaction/control buffer variables record their operation diagnostics.
context_management.transaction_status(bufnr) exposes terminal transaction state.

A retrieval transaction conflict or uncertain outcome stops later internal loop
writes and callbacks and blocks further runs for that buffer. Terminal cleanup
releases reservations and resources and invokes registered ctx.on_cancel handlers.
Those arbitrary trusted Lua handlers may have their own effects; the stop does
not sandbox them. Compare live and disk
transcripts without saving over either version. Preserve divergent versions,
reconcile the intended transcript, then wipe and reopen it before continuing.
There is no reset command. Reopening reconstructs remaining pending markers.

						*context_retrieve*
context_retrieve({id, source_index?, offset?, limit?})
        Read a bounded archive page authorized for the calling session.
        Requires enabled context management and a current continuation budget.
        Omit source_index to list source roles, byte sizes, and child IDs.
        Include source_index to retrieve original source text with its role.
        Both forms include recorded tool name/id/error status and block
        coordinates. Only attrs.name, attrs.id and attrs.is_error are exposed;
        unrelated attributes are omitted. Identity strings have a 256-byte
        limit each; oversized metadata refuses rather than truncates identity.
        Encoded metadata and evidence labels count toward the byte allowance.
        offset starts at 1: listing entries or original text bytes.
        limit defaults to 20 entries or 4096 bytes; hard caps are 100 entries
        and 16384 bytes. The available continuation reserve can reduce a page.
        Read next_offset for the next page. Sources precede children in the
        combined listing. Only one page is permitted until a successful
        continuation consumes the protected result. Repeat calls refuse.
        Successful results store context_pending=true in tool-result attrs.
        The loop clears only unchanged results captured in the final request
        after a complete, noncancelled end_turn or tool_use response. Provider
        failure and partial responses retain protection. Reopen and fork infer
        protection from the transcript; disabled legacy compaction, manual
        compaction, and excision also preserve pending results. Editing away
        the attribute releases protection without proving consumption.
        Pending markers grant no archive access or instruction authority.
        Originals are labeled untrusted archived evidence. Archived roles
        describe provenance and do not give the text new authority. The tool
        has trusted capability="read", including for read-only children;
        session ownership still restricts which archives the child may read.

						*fn.context_budget*
fn.context_budget(prepared, ctx) -> budget
        prepared = {body, provider, model?, model_entry?, output_reserve?,
                    route, calibration_identity?}
        Built-in body is final provider JSON, including system text and tools.
        model_entry supplies input_limit/context_limit/context metadata.
        Custom-provider preparation uses {body = req, provider = "custom",
        route = "custom", output_reserve?}; configure conservative input_limit.
        Accounting cannot inspect a custom provider's eventual wire request.

        Default result = {tokens, limit, source, exact = false, safety_margin,
          provider, model?, route, output_reserve?, fingerprint,
          cache = {configured_retention?, observed = "unknown", expiry = "unknown"}}
        fingerprint hashes the UTF-8-scrubbed serialized body. Calibration adds
        observed_input, delta_bytes, calibration_identity, and changes source
        to "observed input + wire-byte delta estimate". Replacement counters
        must return nonnegative numeric tokens and positive finite limit;
        retain source/exact for diagnostics and policy input.

        Enabled file-backed sessions record successful noncancelled built-in
        usage observations. Input totals sum normalized input_tokens and
        optional cache_read_input_tokens/cache_creation_input_tokens.
        OpenAI normalization subtracts cached tokens from inclusive input
        before exposing the cache-read component; Anthropic-compatible usage
        separates uncached input and cache components. Each is added once.
        Invalid or missing input usage supplies no observation.
        Reuse requires matching provider/model/route, hashed endpoint/account
        identity, provider/auth source identities, identical nonmessage fields,
        and an exact ordered message prefix with optional final-content extension.
        Earlier edits, compaction, changed tools/system/settings or identities
        prevent reuse and restore wire-byte accounting until a compatible
        observation exists. Added bytes use the configured rate/margin plus
        64 tokens. exact remains false; acceptance is not guaranteed.
        Isolated summaries neither observe nor use session calibration.
        Observations remain in memory until buffer wipe and measure neither
        cache residency nor expiry.
						*fn.context_summarize*
fn.context_summarize(req, ctx) -> result
        req = {system, sources, tools = {}, tool_choice = "none",
               max_output_tokens, phase = "leaf" or "merge"}
        Leaf sources carry ref, kind, text, optional id/attrs/block coordinates,
        source_index, start_byte/end_byte, and continuation =
        {before, after, total_bytes}. Merge sources carry ref, kind = "summary",
        text, depth, and original_ranges.

        result = {summary, complete = true, source_refs,
                  stop_reason = "end_turn" or "stop", truncated?, tool_calls?, usage?}
        summary must contain nonblank text. source_refs must match every supplied
        ref once in order. truncated=true and nonempty tool_calls refuse.
        Optional usage requires nonnegative integer input_tokens/output_tokens
        and optional cache_read_input_tokens/cache_creation_input_tokens.
        Total input and output must fit their reservations.
        The default uses the configured provider with no tools or transcript
        streaming and decodes response text as JSON. Custom implementations
        must honor limits and the source contract and raise on provider failure.
        context_summary.new_attempt/generate convert failures to
        nil, message, {kind = "invalid", "budget", "cancelled", "generation",
        or "internal"}. The registry function does not return that tuple.

        Configure bounded summary mode and an explicit override after setup: >lua
  require("straps").setup({context_management = {
    enabled = true, mode = "summary", input_limit = 100000,
    summary = {max_input_tokens = 8192, max_output_tokens = 1024,
      max_total_tokens = 65536, max_calls = 32, max_depth = 4, max_retries = 0},
  }})
  require("straps.registry").define({
    name = "fn.context_summarize", kind = "fn", source = [[
      return function(req, ctx)
        return require("straps.context_management").summarize(req, ctx)
      end
    ]],
  })
<
        The example delegates to the default generator. Replace the delegation
        with a generator satisfying the same contract. Selecting summary mode
        permits provider spending at automatic boundaries; setup alone does
        not generate a summary.

						*straps-subprocesses*
SUBPROCESS GATE~

A counting semaphore shared by `bash`, `run_in_terminal`, `run_quickfix`, `fetch_url` and
`grep` bounds how many straps-launched processes run at once across every
session in this Neovim. Without it, N sessions together start N times the
processes one session would. Four entries, each redefinable on its own; a
plugin shadows the one it wants:

						*fn.subprocess_in_flight*
fn.subprocess_in_flight()
		Slots held right now: a read accessor over the counter that
		|fn.subprocess_acquire|'s take/release write.
		|fn.subprocess_threads| reads it; a redefined limit fn can.

						*fn.subprocess_limit*
fn.subprocess_limit()
		Policy: how many may run. Default `max_subprocesses` (nil
		-> 2 * CPU count), halved while the 1-minute load average
		exceeds 2 * CPU count. Consulted at every admission.

						*fn.subprocess_threads*
fn.subprocess_threads()
		CPU count divided by the slots in flight, floor 1. `grep`
		passes it as `rg --threads`, so a lone session searches
		with every core and a fan-out shares them.

						*fn.subprocess_acquire*
fn.subprocess_acquire({ctx}, {info})
		Mechanism: take a slot, waiting through `ctx.await` while
		in_flight >= limit (FIFO). `info` is `{ tool, bufnr, cmd }`.
		Returns an idempotent release function, also registered via
		`ctx.on_cancel`, so a cancelled or backstop-resumed holder
		frees its slot. Release runs before the kill, so a process
		that survives its group kill runs uncounted; the gate stays
		open. A parked waiter whose run was cancelled declines its
		slot, and a run cancelled between admission and resume errors
		instead of starting its process. Waiters admitted from a
		`vim.system` exit callback are admitted on the main loop in
		the global registry scope; admissions from a tool body run in
		that session's scope, so define a replacement limit fn
		globally. A ctx without await is admitted at once and may
		exceed the limit by one. The tools pcall the spawn and release
		on failure, so EAGAIN cannot leak a slot. Redefine for
		priority or per-session fairness.

10. SKILLS						*straps-skills*

A skill is knowledge, not capability: stored prose (a procedure, a subsystem's
true shape) loaded into the conversation when its trigger matches. Skills are
`skill.*` registry entries or SKILL.md files on disk (|straps-skill-files|);
the agent lists them with the `skill` tool and loads one by name. Define one
with `registry_define` (kind "skill", source = the prose). Contrast with
tools/hooks/fns, which add capability.

Two skills ship as builtins: `skill.showing_user` — the full presentation
guidance behind the core prompt's `# Showing the user` stub, loaded before
building a hand-off view — and `skill.multiplayer`, the protocol for working
alongside another agent in the same Neovim (see |straps-multiplayer|). Both
are registered with define_default, so redefining them survives re-running
setup().

SKILL.md files						*straps-skill-files*

Skills in the Agent Skills format (https://agentskills.io/specification) are
also found on disk: a directory holding a `SKILL.md` whose YAML frontmatter
has `name` and `description`, followed by a markdown body.
`fn.discover_skills` scans these roots in order, and a later root wins a name
collision:

	~/.agents/skills
	~/.claude/skills
	stdpath("config")/straps/skills
	.agents/skills, then .claude/skills, in the cwd and each ancestor,
	    farthest first, excluding $HOME and above (every ancestor when
	    the cwd is outside $HOME)
	config.skill_paths

Each immediate subdirectory of a root that contains a file named `SKILL.md`
is one skill. The `# Skills` prompt section lists it as
`- <name>: <description>` without file paths, and the `skill` tool loads its body
plus a footer naming the skill directory and up to 50 bundled files, sorted,
at most three directory levels deep (listed, not read; the list is marked
truncated past 50 files or when entries remain past 2000 scanned).

A name that starts with `-` or has characters outside [A-Za-z0-9_-], an empty
description, a missing or unclosed frontmatter, or a frontmatter longer than
400 lines skips the file; other spec violations only warn. Discovered skills
are files, not registry entries: registry_list and registry_get do not show
them. A `skill.<name>` registry entry of the same name shadows the file.
Discovery reruns for each new session and each `skill` call, so an edited
`SKILL.md` takes effect without a restart.

Project-tier skills load without a trust prompt, like AGENTS.md: a cloned
repository's skill descriptions enter the system prompt. Each SKILL.md and
each listed bundled file must resolve inside its skill directory: a bundled
symlink is listed only when it points to a regular file inside that
directory, and symlinked directories are not followed. A skill whose path
contains a control character is skipped. `:checkhealth straps` lists
discovered skills, shadowed ones, and parse diagnostics. Set
`skill_discovery = false` to turn discovery off.

11. SUBAGENTS						*straps-subagents*

`spawn` launches a subagent in its own session buffer and returns immediately
with a handle; the child runs concurrently. `spawn_wait` blocks on one or more
handles and returns their final answers — waiting on N children costs the
slowest, not the sum. Issue N `spawn` calls in one turn to fan out. A message
for the waiting session (from you, a peer, a child, or the harness) ends the
wait early: the result lists each child still running, the message follows,
and the agent calls `spawn_wait` again to keep waiting. A child left running
this way still sends its completion notice when it ends.

A parent does not have to block, and the system prompt tells the agent not to:
work that does not depend on a child's answer should proceed while the child
runs. When a child's run ends,
|hook.on_run_end.notify_parent| delivers one line to the parent naming the
child's buffer, its task, the outcome and how to collect it — as steering if
the parent is running, as an ordinary user block if it is idle. The notice
never starts its parent's run; a parent that wants to be started when a child
ends watches it with |watch_agent|. So "spawn, keep working, collect when the notice
lands" is the default shape, and `spawn_wait` in the same turn as `spawn` is
for when the child's answer is the next step; `spawn_wait` on a child that
already finished returns at once. The notice never carries the child's answer
text: the point of a subagent is that its context stays its own. Collecting a
child with `spawn_wait` silences its notice, a child the user stopped is
silent, and `spawn_notify = false` turns the whole thing off.

A child is a full session: its transcript is a real buffer the user can open
(`show = true`), watch and steer. It inherits the parent's registry view but
anything it defines lands in its own scope. Use it to isolate a broad
investigation so the parent transcript keeps only the conclusion. Without a
`provider` argument, a child uses its parent's resolved provider. Without a
`model` argument, it inherits the parent's model for that provider.

`spawn` takes `allow` (an array of strings) to grant the child permission
categories. Each entry is a grantable category (see |fn.capability|) or a
specific tool name; an unknown entry errors at spawn time, and so does any
bare entry in the `define` category (`"define"` or `registry_define`).
`allow={"lua"}` permits ordinary session extensions; readonly children may
define session skills. Restricted children deny direct global or protected
definitions. A tool-name grant covers exactly that tool even when its
category is not granted.
child gets a confirm shadow: read-only calls, granted categories/tools,
builtin watch/unwatch calls on any agent, and messages to `"parent"` run
unprompted. Every other call is denied without a dialog. `readonly = true`
is the same as `allow = {}`, including those watch and messaging exceptions.
`readonly` and `allow` together error.
See |straps-auto|.

Subagents nest as deep as `max_spawn_depth` allows (default 1: children
cannot spawn). A child with depth budget left, whose own gate would pass a
spawn call, keeps the `# Subagents` prompt section and sees `spawn`; a child
at the limit sees neither, and a `spawn` call from there is refused. A
readonly/allow child is a permission ceiling for
its own children. Each `allow` entry it passes must be within its own grants:
a category it holds, a tool name it holds, or a tool whose category it holds;
read-only tools always pass. An entry outside them errors at spawn time. A
child it spawns without `allow`/`readonly` is made read-only, and the `spawn`
result says so. A gated child that was not granted `spawn` sees no `spawn`
tool. An ungated session (the user's confirm dialog or |:StrapsAuto| is its
gate) is under no ceiling. |:StrapsStop| on a session stops every running
descendant.

|:StrapsAgents| opens the agent dashboard. Loaded sessions retain their
parent/child tree when a run finishes. Saved transcripts appear separately.
Use native folds to collapse trees and sections, and native search to find
rows. Rows fit the narrowest dashboard window; long titles and tasks collapse
whitespace and truncate with an ellipsis instead of overflowing.

Dashboard keys:
  <CR>       Open the selected transcript in the dashboard window.
  g<CR>      Start or continue the selected idle session.
  i          Message the selected session; an idle recipient does not start.
  x          Stop a running session; confirm descendant cancellation. Like
             |:StrapsStop|, this pauses |watch_agent| wakes for the session.
  r          Rename the durable title without changing the transcript path.
  R          Clear cached saved summaries and refresh.
  p          Open selected-agent details in a read-only split.
  P          Toggle detail follow-selection; disabled initially.
  <F1>       Open dashboard help.

The detail split shows task, status, model, context, parent, and a bounded
assistant-text preview from the loaded buffer. The preview searches the last
256 lines and shows at most 12 assistant-text lines, capped at 240 display cells
per line. Open the transcript for text outside those bounds. The detail split
does not generate a summary.
Use <C-w>s or <C-w>v followed by <CR> to open a transcript in another split.
Native /, ?, Visual mode, and window commands retain their meanings.
Refresh preserves selection, viewport, and folds. Status uses observed run
phases and ending reasons; a tool phase alone does not imply user input is
needed. Saved summaries use a display-only memory cache; R forces a rescan.

12. MULTIPLAYER						*straps-multiplayer*

Several agents can run in ONE Neovim at once — subagents, or independent
sessions you started yourself. They share buffers, so a peer's unsaved edits
are already in the text another agent reads, and the file on disk is a thing
they both write. Two mechanisms make that workable.

Detection, at the moment of collision: every buffered write stamps the file
buffer with the writing session, and an edit whose file was last changed by
ANOTHER session fails with "modified by another agent (session N, task: ...)"
rather than clobbering it. Re-read the file and reapply if the change still
applies.

Awareness, before the collision:

						*straps-models-tool*
models		Tool. Lists the models available to this session: each id
		exactly as |tool.spawn|'s `model` argument takes it, its
		capability/cost label, its context window, and the effort
		names, with the session's active model marked. Reads the
		configured/discovered catalog for the active provider (no
		network call; |:StrapsModel| refreshes it). Read-only and
		auto-allowed. Pairs with |fn.model_note|, which says
		which of them you are running.

			*straps-agents-tool*
agents		Tool. Lists every other session in this Neovim: running or
		idle, its relation to the caller (parent/child/sibling/peer),
		the task it was given, and the files it has written.
		Read-only and auto-allowed. `fn.peer_agents(bufnr)` is the
		underlying snapshot.

hook.on_run_start
		When a run starts while other agents are running, appends one
		user block naming them and pointing at the agents tool. Silent
		for a solo session, silent when the same peer set was already
		announced, and silent on a transcript with nothing else to
		send. Redefine it to reword or disable the notice.

skill.multiplayer
		The protocol the notice points at: re-read and reapply after a
		collision, keep the read-to-write gap short, prefer disjoint
		files, leave a peer's mid-task work alone, and hand off with
		`send_message` rather than racing.

Handing off, when one agent needs another to act:

					*straps-send-message-tool*
send_message	Tool. Send a message to another session in this Neovim:
		`to` is its buffer number as digits or `"parent"`, `text` at
		most 4000 bytes. The message arrives in the recipient's
		transcript as a user-role block framed
		`[straps] from agent <label> (buffer N): ...`, which renders
		as `agent N` (see |straps-highlights|, StrapsRoleNotice)
		rather than as the user, and which the system prompt ranks
		as a peer's claim below the user's instructions. A running
		recipient reads it at its next turn boundary (steering); an
		idle one finds it appended and is NOT started. On an idle
		session the block lands after any text the user had typed in
		the trailing prompt. In the `spawn` permission category
		(|fn.capability|): a top-level session confirms each send
		unless `:StrapsAuto spawn` is set. A readonly/allow-gated
		child may always send `to="parent"`; any other target needs
		a grant and must be its parent, one of its own children, or
		an immediate sibling sharing a valid session parent.

					*straps-watch-agent-tool* *watch_agent*
watch_agent	Tool. Subscribe to another session's lifecycle: `to` is its
		buffer number as digits or `"parent"`; `events` is any of
		`run_start`, `run_end`, `closed` (default `run_end` and
		`closed`); `wake` defaults to true. When a watched event
		fires, a `[straps] watched agent <label> (buffer N): <event>`
		notice reaches the watcher: as steering if it is running (a
		`spawn_wait` it is blocked in returns early), and if it is
		idle with `wake` true, the notice is queued and its run is
		STARTED. Each watch fires once and is then removed. A stopped
		run (by you, its parent's stop, or a `spawn_wait` timeout)
		notifies nobody and leaves the watch armed. `closed` fires
		when the buffer is unloaded or
		wiped, once, and never while Neovim exits. An idle watcher is
		not started, and the notice is appended instead, when:
		- `wake` is false;
		- its trailing prompt holds text you have not sent;
		- you stopped it with |:StrapsStop| or the dashboard `x` key;
		- it has used `watch_wake_limit` wakes since you last sent
		  to it or started it.
		A parent watching its own child receives both the watch
		notice and the subagent completion notice; only the watch
		starts an idle parent.
		Both tools use the `spawn` category for top-level confirmation.
		Readonly and allow-gated children may watch any agent without
		a grant, including with automatic wakes.
unwatch_agent	Tool. Remove only this session's watch on `to`. Readonly and
		allow-gated children may remove their watches on any agent.
Harness notices use the same mechanism: a user block beginning `[straps] `
(the multiplayer notice, a subagent completion notice) renders as `harness`.
The prefix is a content convention, so a block you type yourself starting
with `[straps] ` (or with the agent frame above) renders the same way; the
model is told the prefix is advisory and that a real instruction from you
overrides it.

All of this is same-instance only: agents in a DIFFERENT Neovim share nothing
but disk, where the only signal is a file changing underneath you.

13. AUTO MODE						*straps-auto*

Auto mode grants whole permission categories so the matching tool calls run
without a confirm prompt. |fn.capability| classifies every call into a
category. The grantable categories are `edit`, `delete`, `exec`, `lua`, `net`,
and `spawn`. The `read` category is always auto-allowed. The `define` and
`agent_tool` categories are never grantable.

The `lua` category also covers structurally valid session-local
`registry_define` requests for tools, hooks, and functions, plus calls to
session-scoped tools without explicit trusted capability metadata. The grant
covers their later revisions. Session skill definitions use `read`, although
they mutate the session registry. Direct global definitions, malformed or
unclassified definition requests, and protected definitions use `define`.
Protected names are `hook.confirm`, `fn.capability`, `fn.readonly_policy`,
`tool.registry_define`, `hook.guard`, and `hook.guard.*`. A session shadow of
`tool.registry_define` remains `define` when invoked. These direct requests
require confirmation, with no blanket "Always this tool" approval or
registry_define tool-name grant bypass. Unknown global tools remain
`agent_tool`. Manual combined define-and-use approval is deferred.

These rules classify dispatched direct requests. Arbitrary Lua retains
Neovim process privileges; the rules do not sandbox it. Contextual dispatch
retains ancestor ceiling checks and definition identities. Transcript
excision permissions are unchanged.
Grant categories to the current session with |:StrapsAuto|: >vim
	:StrapsAuto edit,exec   " allow edits and shell commands
	:StrapsAuto             " choose grants with Snacks, else report grants
	:StrapsAuto off         " clear all category grants
<
A new session can start with grants: `:Straps edit,exec` (or `:Straps all`)
grants them before the first request, so a shell can start Neovim in an
auto-mode session: `nvim +'Straps! exec -- run the tests'`. See |:Straps|.

Grants are stored as `cap:<category>` keys in the registry's per-session grant
set (`registry.granted(bufnr)`; not a buffer variable, which any Lua the agent
runs could write). `off` clears
only those keys, so editdir: and per-tool grants stay. Grant categories to a
subagent with `spawn`'s `allow` (see |straps-subagents|). Category grants are
path-unrestricted: an `edit` grant covers every path, including a trusted
`.straps.lua`.

For finer-grained policy, redefine |fn.capability|. The redefinition must
classify the calls you want into a new category AND add that category to the
grantable list it returns with no arguments — |:StrapsAuto| and `allow`
validate against that list. For example, classify git-only `bash` as a `vcs`
category, add `vcs` to the grantable list, then `:StrapsAuto vcs` grants it. >lua
	require("straps.registry").define{
	  name = "fn.capability", kind = "fn",
	  doc = "git-only bash is its own 'vcs' category",
	  source = [==[
	    local base = require("straps.registry").bind("fn.capability")
	    return function(name, input)
	      if name == nil then
	        local g = base(); table.insert(g, "vcs"); return g
	      end
	      if name == "bash" and type(input) == "table"
	        and type(input.command) == "string"
	        and input.command:match("^git%s") then
	        return "vcs"
	      end
	      return base(name, input)
	    end
	  ]==],
	}

14. HEALTH						*straps-health*

						*straps-checkhealth*
>vim
	:checkhealth straps
<
Diagnoses everything that can be wrong before a session runs: the Neovim
version, `curl` (and optional ripgrep), the API key (the provider's base URL,
which source the key fn returned a key from, the ChatGPT login's expiry for
OpenAI, and problems: a stored key file accessible by group or other,
unreadable or malformed, a dangling symlink, a non-file at the key path or a

probe is isolated, so the report runs even when `setup()` never ran or the
data dir is unwritable.

16. EVENTS						*straps-events*

						*b:straps_status*
b:straps_status		"running" while a run is active in the session
			buffer, "idle" once it has ended.

						*b:straps_run_reason*
b:straps_run_reason	The last observed run-ending reason: "ok",
			"cancelled", "max_turns", "stalled", "blank", or
			"error". Cleared when a new run starts. This value
			belongs to the loaded buffer and is not persisted.

The loop fires these |User| autocmds on every run, from the loop itself, so
redefining `hook.on_run_start` or `hook.on_run_end` does not silence them.
Each callback receives the fields below in `args.data`.

						*StrapsRunStart*
StrapsRunStart		A run started. `data = { bufnr }`.
						*StrapsRunEnd*
StrapsRunEnd		A run ended. `data = { bufnr, reason, turns }`.
			`reason` is "ok", "cancelled", "max_turns",
			"stalled", "blank" or "error"; `turns` is the
			number of turns the run took.
						*StrapsStatusChanged*
StrapsStatusChanged	Fired right after each |b:straps_status| change.
			`data = { bufnr, status }`. At run end it fires
			before |StrapsRunEnd|, so a StrapsRunEnd callback
			that starts another run sees no stale idle event.

Example: notify when an agent finishes, and a bufferline component: >lua
	vim.api.nvim_create_autocmd("User", {
	  pattern = "StrapsRunEnd",
	  callback = function(args)
	    vim.b[args.data.bufnr].straps_done = true
	    vim.notify(("straps: buffer %d done (%s)")
	      :format(args.data.bufnr, args.data.reason))
	  end,
	})
	local function straps_component(buf)
	  local s = vim.b[buf].straps_status
	  return s == "running" and "●" or (vim.b[buf].straps_done and "✓" or "")
	end
