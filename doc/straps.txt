1. INTRODUCTION						*straps-introduction*

straps.nvim is a small, legible harness for coding agents that live inside
Neovim. Three invariants govern the whole design:

1. Buffers are state. The conversation transcript IS a buffer in a parseable
   marker format. Each turn the loop re-parses the buffer to build the API
   request, so editing history, the system prompt, or an old message is a
   first-class action — the buffer is canonical.

2. Everything is late-bound and redefinable. Every tool, hook, the provider
   and the key loop functions are entries in a registry, stored as Lua source
   strings, compiled on define and looked up by name at every call. A
   redefinition takes effect on the very next call, even mid-run.
   See |straps-registry|.

3. The agent can extend itself. The agent has registry introspection and a
   define tool, and the tool list sent to the API is rebuilt from the registry
   every call, so a tool the agent defines in one turn is callable the next.

Requirements: Neovim >= 0.11, and `curl` on $PATH. No other dependencies.
Run |:checkhealth| straps to verify your install — see |straps-health|.

2. SETUP						*straps-setup*

						*straps.setup()*
>lua
	require("straps").setup({
	  model = "claude-sonnet-5",
	  default_max_tokens = 32000,
	})
<
`setup()` merges your options into |straps-config|, then registers the default
provider, tools, editor tools and UI. It is idempotent: registration uses
`define_default`, which skips names that already exist, so a redefinition
(yours or the agent's) survives a re-run of `setup()`.

The API key is read by |fn.api_key|: `$ANTHROPIC_API_KEY` first, then the
first line of `$XDG_CONFIG_HOME/straps/api_key` (which must be chmod 600).

The commands work without `setup()` (they `require` lazily), but folding, the
`gf` mapping and rendering are only fully wired once `setup()` has run.

3. COMMANDS						*straps-commands*

							*:Straps*
:Straps			Open a new session buffer in a split and put the
			cursor on the trailing user block. See
			|straps-session|.

							*:StrapsResume*
:StrapsResume [{name}]	Resume a saved session. No argument resumes the most
			recent; an argument is a session basename (completed
			from saved sessions) or a path. This reopens a
			transcript from disk; it does not restart a run — for
			that see |:StrapsContinue|.
:StrapsResume!		Open a picker over all saved sessions. Each row shows
			the session's durable title (see |:StrapsRename|) or,
			absent one, its first user prompt, plus a relative age
			— so sessions are identified by what they were about,
			not by a timestamped filename. With snacks.nvim present
			the picker fuzzy-matches those rows and previews the
			transcript; otherwise it is a |vim.ui.select| list.

							*:StrapsRename*
:StrapsRename [{title}]	Give the current session a durable title, stored in a
			companion "<transcript>.meta" file (the transcript
			itself is untouched). The title is what |:StrapsResume!|
			shows for the session. No argument prompts for one
			(pre-filled with the current title); an empty title
			clears it.

							*:StrapsSearch*
:StrapsSearch {pattern}	Full-text search across every saved transcript for
			{pattern} (ripgrep when available, else |:vimgrep|) and
			load the conversation matches — transcript scaffolding
			is skipped — into the |quickfix| list, so |:cnext| /
			|:cprev| step through them and <CR> opens the transcript
			at the hit. Finds a session by what was said in it.

							*:StrapsSend*
:StrapsSend		Send the current session buffer as-is. If a run is
			already active, prompt for a steering message
			(|straps-steering|) instead. Also bound to <CR> in a
			session buffer. Errors if the trailing user block is
			empty, or if the transcript ends on an assistant
			message (unsupported prefill) — which is what a
			stopped run leaves, so use |:StrapsContinue| there.

							*:StrapsSteer*
:StrapsSteer {text}	Queue {text} as a steering message on the active run
			(|straps-steering|).

							*:StrapsStop*
:StrapsStop		Request cancellation of the active run. The run
			notices between turns and between tool calls, kills an
			in-flight request or `bash` process, and ends with a
			note appended to the transcript. To pick the work back
			up, see |:StrapsContinue|.

							*:StrapsContinue*
:StrapsContinue [{text}]
			Continue a run that was stopped (|:StrapsStop|) or
			interrupted, in the current session. There is no run
			state to restore — the buffer IS the state — so this
			just appends a user block ({text}, or a generic
			"continue where you left off") and sends: the stopped
			transcript is already well-formed, it merely ends on an
			assistant block, which cannot be sent as-is. The
			continued run gets a fresh |straps-config| `max_turns`
			budget, a fresh stall counter and fresh blank-turn
			nudges; the conversation itself is unaffected. Errors
			if a run is already active — |:StrapsStop| it first, or
			|:StrapsSteer| it instead. Distinct from
			|:StrapsResume|, which reopens a saved transcript from
			disk.

							*:StrapsAuto*
:StrapsAuto [off|{cats}]
			Grant capability categories to the current session so the
			matching tool calls run without a confirm prompt (session
			buffers only). `:StrapsAuto edit,exec` grants those
			categories, no argument reports the current grants, and
			`off` clears every category grant (leaving editdir: and
			per-tool grants intact). Completion offers `off` and the
			grantable categories. See |straps-auto| and |fn.capability|.

							*:StrapsCompact*
:StrapsCompact		Mechanically compact the current transcript — shrink
			old tool_use/tool_result contents in place — and
			notify the summary. See |fn.compact|.

							*:StrapsEdit*
:StrapsEdit {name}	Open registry entry {name} (e.g. `fn.render`,
			`hook.confirm`, `tool.bash`) as an executable Lua
			buffer. Writing the buffer (|:w|) re-executes it,
			redefining the entry. Completion lists every entry.
			See |straps-registry|.

							*:StrapsRegistry*
:StrapsRegistry		Open a scratch listing of every registry entry;
			<CR> on a line opens that entry with |:StrapsEdit|.

							*:StrapsHelp*
:StrapsHelp [tag]	Open |:help| for straps (default tag `straps`, or
				a supplied straps help tag such as `straps-tools`).

							*:StrapsEval*
:StrapsEval		Execute the current buffer as Lua.

							*:StrapsAgents* *straps-agents*
:StrapsAgents		Open the agents buffer (straps://agents): one ordinary
			buffer listing every session in three sections —
			running, loaded (idle, with age and context fill when
			known), and saved (on disk). Manage them with a small
			keymap grammar: <CR> open, x stop, i steer,
			r rename, R refresh — shown in the window's winbar
			(config `agents_winbar = false` puts it on the first
			line instead). <CR> replaces the agents buffer in
			its own window (oil-style), so <C-o>/<C-i> step back to
			the list and forward again. It re-renders as runs start,
			work and finish. Takes the same |<mods>| as |:Straps|
			(:vertical StrapsAgents for a vsplit).
			See |straps-agents| and |straps-subagents|.

							*:StrapsModel*
:StrapsModel		Pick the provider-specific model for the current session
			(or global default off a non-session buffer). Does live
			discovery via |fn.list_models| and merges your account
			catalog over `models` or `openai_models`.

							*:StrapsEffort*
:StrapsEffort		Pick the extended-thinking effort (off/low/medium/high
			by default) for the current session or globally.

4. THE SESSION BUFFER					*straps-session*

A session is a single ordinary buffer — there is no separate compose window.
You type your message directly under the trailing `%%[straps:user]%%` marker,
the same buffer the loop reads and appends to. Editing earlier history before
you send is intentional, not an accident.

Sessions are durable: the buffer is backed by a real file under
|straps-config| `session_dir` (`*.straps`), persisted at every block boundary,
so it survives a restart and |:StrapsResume| just reopens it.

Because persistence happens at block boundaries, a session whose Neovim died
while a tool was still running is saved with a `tool_use` block that never got
its `tool_result` — a shape the API rejects. |:StrapsResume| repairs that on
open: each unfinished tool call gets an error result ("run interrupted before
this tool finished") and the trailing user block is restored, so the resumed
session can be sent. |:StrapsContinue| then picks the work back up. Two things
are deliberately left alone: a session that still has a run in flight (a
running tool is indistinguishable from an interrupted one, so repairing it
would report a false failure), and a transcript whose tool blocks were
hand-edited into an inconsistent state — that still fails loudly when sent.

Buffer-local mappings (normal mode):
	<CR>	Send, or prompt to steer if a run is active (|:StrapsSend|).
	gf	Open the `path:line[:col]` reference under the cursor. Also
		active in any hand-opened `*.straps` file.

Transcript grammar. Blocks are marker lines `%%[straps:KIND]%%` (with compact
JSON attrs for tool blocks) followed by content; KIND is one of
`system user assistant tool_use tool_result`. `fn.render` (|straps-fn|) draws a
display-only layer of conceal + extmarks + folds over the raw markers; nothing
mutates the buffer text. `:set conceallevel=0` reveals the raw markers, and
|straps-config| `render = false` turns the whole layer off.

							*straps-steering*
Steering. A message sent while a run is active is queued (not started as a new
run) and drained into the transcript at the next turn boundary, so the model
acts on it mid-flight. |:StrapsSteer| queues directly; <CR>/|:StrapsSend|
prompt for the text.

Progress. While a run is active a virtual-text indicator on the last line
shows the phase, elapsed time, stream liveness and the stop/steer hints. The
policy is the redefinable |hook.on_progress|.

Winbar. Session windows get a window-local winbar showing the effective model,
effort and run status, plus live token usage once the first response arrives —
the context fill (e.g. 47.0k/200k (24%)) and cache hit rate, from
`ui.usage_status()`. Disable with |straps-config| `session_winbar = false`.

Own components. `ui.session_info(bufnr)` returns the session's RESOLVED state
(provider, model, model_label, effort, overridden, status, parent, usage,
context_used, context, context_pct, cache_pct), or nil when bufnr is not a
session buffer; bufnr defaults to the current buffer. The buffer variables are
raw — an unset override says nothing about the effective value — so build
statusline/winbar components on session_info rather than on b:straps_model.
`ui.session_status()`, `ui.usage_status()` and `ui.session_winbar()` all take
the same optional bufnr, and `ui.human_tokens(n)` formats a token count.
Note a GLOBAL tabline cannot resolve the session implicitly: %{} there (and
bufnr() inside it) evaluates in the current window's context. Pass a bufnr
from a Lua component framework, or use `ui.agents_status()`.

5. CONFIGURATION					*straps-config*

Pass these to |straps.setup()|. Defaults shown.

						*straps-config-model*
model			(string) "claude-sonnet-5". The request model.
max_tokens		(number|nil) nil. Response token cap per call. nil uses
			the active model's own max output (the matching
			|models| entry's `max_output`, else
			`default_max_tokens`). A number pins an explicit hard
			cap that wins, except a budget-thinking request still
			bumps above it when it would be <= budget_tokens (the
			API rejects that). OpenAI: max_tokens else
			default_max_tokens (no per-model discovery).
default_max_tokens	(number) 32000. Fallback cap when max_tokens is nil and
			the model has no known max_output; also the OpenAI
			default.
max_turns		(number) 128. Hard backstop on turns per run; a
			visible note is appended when hit.
stall_limit		(number) 6. End a run after this many CONSECUTIVE
			stalled turns (every tool call errored, or a
			(tool,input) call repeated). 0 disables the detector.
stop_backstop_ms	(number) 4000. |:StrapsStop| backstop: a run still
			suspended on the same await this long after the
			cancel handlers fired is forcibly resumed, so the
			wedged tool errors and the run ends with the normal
			cancellation note.
blank_nudge_limit	(number) 1. Catches a turn that ends with no tool
			call and no visible text ("runs a command then
			returns silence"). Nudges the model to report or
			continue up to this many times, then ends loudly
			with reason "blank". A blank max_tokens turn ends
			loudly with no nudge. 0 skips the nudge.
max_tool_result_bytes	(number) 100000. Tool results larger than this are
			truncated with a note.
cache			(boolean) true. Anthropic prompt caching via
			cache_control breakpoints. Set false for strict
			servers that reject unknown fields.
cache_ttl		(string|nil) nil (5-minute default TTL). "1h" opts
			into the 1-hour extended TTL on every breakpoint.
compact_keep_turns	(number) 2. Assistant turns |fn.compact| keeps intact.
after_write_diagnostics	(boolean) true. Default |hook.after_write|: feed the
			attached LSP's ERROR/WARN diagnostics for a written file
			back into the tool result. false makes the hook a no-op.
after_write_diagnostics_ms (number) 800. How long that hook waits for the
			language server to re-lint before reporting.
instructions_files	(list) {}. Extra memory files included in the system
			prompt after AGENTS.md/CLAUDE.md.
session_dir		(string|nil) nil -> stdpath("data")/straps/sessions.
			Where `*.straps` transcripts are written.
auto_compact_tokens	(number|nil) nil (off). Auto-compact when the estimated
auto_compact_bytes	context passes this threshold. Both off by default.
render			(boolean) true. Master switch for the |fn.render|
			presentation layer.
tools_expanded		(boolean) false. Fold tool blocks OPEN by default.
session_winbar		(boolean) true. Window-local winbar on session windows.
agents_winbar		(boolean) true. The agents buffer's keymap legend in a
			window-local winbar; false = first buffer line instead.
models			(list) 4 curated Anthropic entries { id, label?,
			thinking?, context?, max_output? }. The |:StrapsModel|
			Anthropic seed/cache; `thinking` is "adaptive" or
			"budget", `context` is its input window, and
			`max_output` is its max response tokens (the default
			max_tokens for that model). An unlisted Anthropic
			model sends no thinking block.
openai_models		(list) curated OpenAI entries { id, label? }. The
			|:StrapsModel| OpenAI seed/cache, separate from
			`models` so provider switches do not show stale ids.
context_window		(number|nil) 200000. Fallback token window for a model
			with no `context` in the active provider's model list,
			used only to render the winbar's context-fill percentage.
			nil hides the %.
effort			(string) "off". Name of the active |:StrapsEffort|
			entry.
efforts			(list) off/low/medium/high, each { name, level?,
			budget_tokens? }.
base_url		(string|nil) nil -> https://api.anthropic.com. Prefixes
			/v1/messages, so a compatible proxy is a config knob.
provider		(string|nil) nil. Backend for |fn.provider|: "anthropic"
			or "openai". nil -> the |:StrapsProvider| persisted
			choice (~/.config/straps/provider) else "anthropic".
			Per session via b:straps_provider.
openai_base_url		(string|nil) nil -> https://api.openai.com. Prefixes
			/v1/chat/completions for the OpenAI backend.
openai_model		(string|nil) "gpt-5". Model id when provider ==
			"openai"; kept separate from Anthropic `model`.
request_timeout_ms	(number) 300000. Idle watchdog: kill a request whose
			stream is silent this long.
log_file		(string|nil) nil (off). Structured JSONL event log; see
			|fn.log|.

							*straps-layers*
layers			(table) { editor = true, openai = true }. Which
			default registration groups |straps.setup()| performs.
			`editor` gates the LSP/tree-sitter tool set
			(lua/straps/editor.lua); `openai` gates the OpenAI
			backend fns (`fn.openai_api_key`, `fn.provider_openai`).
			A registration gate, not a kill switch: false skips
			registering that group; it does not unregister entries
			an earlier `setup()` call already registered (restart
			to drop them), and toggling one back on in a later
			`setup()` call registers its missing entries then.
			With `openai = false`, |fn.provider| errors with a
			clean "openai layer is disabled" message when asked
			to dispatch to "openai", and |fn.list_models| returns
			`(nil, err)` instead of raising.

Per-session overrides live in buffer variables (b:straps_model,
b:straps_effort, ...) set by |:StrapsModel| / |:StrapsEffort| on a session
buffer, so two sessions can run different models at once. The effective
provider/model/effort is also told to the agent by |fn.model_note|, a
"# Model" section appended to each request's system text (never to the
transcript), so a mid-run change is reflected on the next turn.

6. THE REGISTRY						*straps-registry*

The registry is the heart of the plugin. Every tool, hook and core function is
an entry: a Lua source string, compiled on define, looked up by name at every
call site. Names are namespaced `tool.<name>`, `hook.<name>`, `fn.<name>`,
`skill.<name>`.

Scoping. Entries are global by default. A running session can hold
session-scoped shadows that override a global entry for that session (and its
subagents) and vanish when the session closes — the sandbox the agent
experiments in. `registry.remove` drops global entries only.

Versioning. Redefining an entry bumps its `version`; the first-define `seq` is
preserved so the API tool array stays append-only (prompt-cache stable). The
previous source is not retained — there is no built-in rollback; keep your own
copy, or re-render with |:StrapsEdit|.

Persistence. A trusted `.straps.lua` at the project root is loaded
automatically at session start (direnv-style sha256 trust; you are prompted,
defaulting to No, on new or changed content). It is plain Lua:
`registry.define{...}` calls, which is exactly what `registry.render(name)`
emits — so appending a |:StrapsEdit| buffer's content to `.straps.lua` keeps
an entry across restarts. See |straps-health| for the trust state.

Inspect and edit from Lua:
>lua
	local reg = require("straps").registry
	reg.names("tool")          -- list tool names
	print(reg.render("fn.render"))  -- the entry as executable Lua
<
Or from the agent's own tools: `registry_list`, `registry_get`,
`registry_define` (|straps-tools|).

7. TOOLS						*straps-tools*

Tools are what the agent calls. Every one is a registry entry (|:StrapsEdit
tool.NAME|) and every write goes through |hook.confirm|. The defaults:

File & shell:
	read_file, write_file, edit_file, patch_file, path_info, tree,
	fetch_url, glob, grep, bash, run_in_terminal, run_quickfix,
	move_file(s), delete_file(s)

Editor-native (tree-sitter / LSP, degrade gracefully with no server):
	diagnostics, diagnostic_at, diagnostic_next, fix_diagnostic,
	lsp_status,
	declaration, definition, type_definition, implementation,
	references, hover, tree_sitter_status, node_at, read_node,
	symbols,
	read_symbol, workspace_symbols, code_action, rename_symbol,
	format, bulk_replace

Presentation & interaction:
	show_user, show_diff, show_buffer, set_findings, context, ask_user,
	help_search, undo_edit

Self-extension & orchestration:
	registry_list, registry_get, registry_define, skill, eval_lua,
	spawn, spawn_wait (|straps-subagents|), agents
	(|straps-multiplayer|), transcript_excise

`transcript_excise` is context surgery: with no arguments it lists the
transcript's blocks; with `blocks`/`range` and a required `note` it replaces
those blocks' contents with a one-line `[excised: ...]` receipt, so a finished
side quest stops being replayed in later requests. It cannot delete a block,
cannot write text other than the receipt, and never touches the system block or
the turn in flight. `session` targets a subagent's transcript instead.

Writes (write_file/edit_file and the LSP refactors) apply THROUGH the file's
buffer, so they land in the file's native undo tree — the user reverts with
|u|, |:earlier| or undotree, and `undo_edit` can revert a specific past edit.

Run |:StrapsRegistry| for the live list with one-line docs, or `registry_list`
from the agent side.

8. HOOKS						*straps-hooks*

Hooks are the "always do X" seams. Each is a registry entry you can redefine
(|:StrapsEdit hook.NAME|). Redefining "always"-shaped behavior into a hook
beats remembering to repeat it.

							*straps-hooks-fanout*
Fan-out. Some hooks are broadcast to MANY subscribers, not just the one entry
named `hook.NAME`. A subscriber registers itself as `hook.NAME.<suffix>` (e.g.
`hook.after_write.mylinter`). `registry.hook_entries(name)` returns the entry
named exactly `name` PLUS every `hook.name.<suffix>` entry, over the merged
active scope, sorted by registration order (`seq` ascending — the builtin
default first). `registry.call_hooks(name, ...)` runs each with `pcall` so one
broken subscriber cannot stop the others, and returns two tables: `results`
(the non-nil returns, in order) and `errors` (one `{ name, err }` per
subscriber that raised). Add a subscriber with `registry_define` (kind "hook",
name `hook.NAME.<suffix>`); no need to redefine the default.

The fanned-out hooks: |hook.after_write| (all string results appended to the
tool result; a raising subscriber becomes a `[hook <name> error: ...]` line),
and the loop's |hook.on_run_start| / |hook.on_run_end| / |hook.on_turn_start|
/ |hook.before_tool|. |hook.after_tool| is fanned out as a FOLD: each
subscriber gets the CURRENT result and any non-nil return replaces it for the
next one, in registration order. NOT fanned out (single entry, called
directly): |hook.confirm|, |hook.on_progress|, and `hook.on_define`.
						*hook.confirm*
hook.confirm(name, input, ctx) -> allowed, reason
		The permission gate, called before every tool. Default:
		auto-allow the read-only tools; silently allow any call
		whose |fn.capability| category has been granted (a
		`cap:<category>` key in b:straps_allowed, written by
		|:StrapsAuto| or a subagent `allow`); otherwise prompt
		(Yes / No / Always this tool / for edits, Always in <dir>
		/ Always all edits), showing a diff for file edits. Grants
		persist in b:straps_allowed. Never loosen this on the
		agent's initiative. See |straps-auto|.

						*hook.after_write*
hook.after_write(path, ctx) -> string|nil
		Called after write_file / edit_file / patch_file. If it returns a
		string it is appended to the tool result. The default feeds the
		editor's own LSP back to the agent: it waits briefly for the language
		server to re-lint the just-written file, then returns its
		ERROR/WARN diagnostics, so the agent sees breakage it caused
		without being asked. No client on the file, or no new
		diagnostics, appends nothing. Turn off with
		|straps-config| `after_write_diagnostics = false`, or redefine
		it to run an external linter instead. Fanned out
		(|straps-hooks-fanout|): this default plus every
		`hook.after_write.<suffix>` subscriber runs, and all their string
		results are appended in registration order — add a linter without
		replacing the diagnostics default.

						*hook.on_run_start*
						*hook.on_run_end*
hook.on_run_start(ctx) / hook.on_run_end(ctx)
		Called when a run starts / ends (always, including error and
		cancel). on_run_start posts the multiplayer notice when other
		agents are running (see |straps-multiplayer|) and does nothing
		otherwise; on_run_end is a no-op. Redefine either for
		setup/teardown or notifications.

						*hook.on_turn_start*
hook.on_turn_start(ctx, turn)
		Called at the top of every turn, after queued steering drains
		and before the transcript is parsed into the next request — so
		a block it appends belongs to that turn. No-op by default;
		redefine for per-turn budget checks or telemetry.

						*fn.model_note*
fn.model_note(ctx)
		Called each turn by the loop after the transcript is parsed;
		the returned "# Model" section is appended to THAT REQUEST's
		system text (never to the transcript), naming the session's
		effective provider/model/effort so the agent can match a
		subagent's capability to its task instead of inheriting its
		own (the note points at the |straps-models-tool| for the ids
		to pass). Resolved fresh per request, so |:StrapsModel| /
		|:StrapsEffort| retargeting mid-run is reflected on the next
		turn. Returns nil for a non-session buffer; the loop
		pcall-wraps the call, so a broken redefinition degrades to a
		note-less request. Redefine to reshape or silence it.

						*hook.on_progress*
hook.on_progress(ev, ctx)
		Progress display policy. Default draws the virt-text indicator
		on the session buffer. `ev.type` is one of `start` `thinking`
		(with `turn`, `max`) `tool` (with `name`) `tool_done` (with
		`name`, `is_error`) `steer_queued` `done` (with `reason`).

hook.before_tool(name, input, ctx)

10. SKILLS						*straps-skills*

A skill is knowledge, not capability: stored prose (a procedure, a subsystem's
true shape) loaded into the conversation when its trigger matches. Skills are
`skill.*` registry entries; the agent lists them with the `skill` tool and
loads one by name. Define one with `registry_define` (kind "skill", source =
the prose). Contrast with tools/hooks/fns, which add capability.

Two skills ship as builtins: `skill.showing_user` — the full presentation
guidance behind the core prompt's `# Showing the user` stub, loaded before
building a hand-off view — and `skill.multiplayer`, the protocol for working
alongside another agent in the same Neovim (see |straps-multiplayer|). Both
are registered with define_default, so redefining them survives re-running
setup().

==============================================================================
11. SUBAGENTS						*straps-subagents*

`spawn` launches a subagent in its own session buffer and returns immediately
with a handle; the child runs concurrently. `spawn_wait` blocks on one or more
handles and returns their final answers — waiting on N children costs the
slowest, not the sum. Issue N `spawn` calls in one turn to fan out.

A child is a full session: its transcript is a real buffer the user can open
(`show = true`), watch and steer. It inherits the parent's registry view but
anything it defines lands in its own scope. Use it to isolate a broad
investigation so the parent transcript keeps only the conclusion.

`spawn` takes `allow` (an array of strings) to grant the child permission
categories. Each entry is a grantable category (see |fn.capability|) or a
specific tool name; an unknown entry errors at spawn time, and so does any
entry in the `define` category (`"define"` or `registry_define`). A tool-name
grant covers exactly that tool even when its category is not granted. The
child gets a confirm shadow: read-only calls and granted categories/tools run
unprompted, and every other call is DENIED at once — a subagent runs
unattended, so it never waits on a dialog. `readonly = true` is the same as
`allow = {}` (read-only calls only). `readonly` and `allow` together error.
See |straps-auto|.

|:StrapsAgents| opens the agents buffer, which lists running sessions (and
their parents), loaded-but-idle sessions, and saved transcripts on disk.

==============================================================================
12. MULTIPLAYER						*straps-multiplayer*

Several agents can run in ONE Neovim at once — subagents, or independent
sessions you started yourself. They share buffers, so a peer's unsaved edits
are already in the text another agent reads, and the file on disk is a thing
they both write. Two mechanisms make that workable.

Detection, at the moment of collision: every buffered write stamps the file
buffer with the writing session, and an edit whose file was last changed by
ANOTHER session fails with "modified by another agent (session N, task: ...)"
rather than clobbering it. Re-read the file and reapply if the change still
applies.

Awareness, before the collision:

						*straps-models-tool*
models		Tool. Lists the models available to this session: each id
		exactly as |tool.spawn|'s `model` argument takes it, its
		capability/cost label, its context window, and the effort
		names, with the session's active model marked. Reads the
		configured/discovered catalog for the active provider (no
		network call; |:StrapsModel| refreshes it). Read-only and
		auto-allowed. Pairs with |fn.model_note|, which says
		which of them you are running.

			*straps-agents-tool*
agents		Tool. Lists every other session in this Neovim: running or
		idle, its relation to the caller (parent/child/sibling/peer),
		the task it was given, and the files it has written.
		Read-only and auto-allowed. `fn.peer_agents(bufnr)` is the
		underlying snapshot.

hook.on_run_start
		When a run starts while other agents are running, appends one
		user block naming them and pointing at the agents tool. Silent
		for a solo session, silent when the same peer set was already
		announced, and silent on a transcript with nothing else to
		send. Redefine it to reword or disable the notice.

skill.multiplayer
		The protocol the notice points at: re-read and reapply after a
		collision, keep the read-to-write gap short, prefer disjoint
		files, leave a peer's mid-task work alone, and hand off with
		`require("straps.loop").steer(bufnr, msg)` rather than racing.

All of this is same-instance only: agents in a DIFFERENT Neovim share nothing
but disk, where the only signal is a file changing underneath you.

13. AUTO MODE						*straps-auto*

Auto mode grants whole permission categories so the matching tool calls run
without a confirm prompt. |fn.capability| classifies every call into a
category. The grantable categories are `edit`, `delete`, `exec`, `lua`, `net`,
and `spawn`. The `read` category is always auto-allowed. The `define` and
`other` categories are never grantable.

Grant categories to the current session with |:StrapsAuto|: >vim
	:StrapsAuto edit,exec   " allow edits and shell commands
	:StrapsAuto             " report current category grants
	:StrapsAuto off         " clear all category grants
<
Grants are stored as `cap:<category>` keys in b:straps_allowed. `off` clears
only those keys, so editdir: and per-tool grants stay. Grant categories to a
subagent with `spawn`'s `allow` (see |straps-subagents|). Category grants are
path-unrestricted: an `edit` grant covers every path, including a trusted
`.straps.lua`.

For finer-grained policy, redefine |fn.capability|. The redefinition must
classify the calls you want into a new category AND add that category to the
grantable list it returns with no arguments — |:StrapsAuto| and `allow`
validate against that list. For example, classify git-only `bash` as a `vcs`
category, add `vcs` to the grantable list, then `:StrapsAuto vcs` grants it. >lua
	require("straps.registry").define{
	  name = "fn.capability", kind = "fn",
	  doc = "git-only bash is its own 'vcs' category",
	  source = [==[
	    local base = require("straps.registry").get("fn.capability").fn
	    return function(name, input)
	      if name == nil then
	        local g = base(); table.insert(g, "vcs"); return g
	      end
	      if name == "bash" and type(input) == "table"
	        and type(input.command) == "string"
	        and input.command:match("^git%s") then
	        return "vcs"
	      end
	      return base(name, input)
	    end
	  ]==],
	}
<

14. HEALTH						*straps-health*

						*straps-checkhealth*
>vim
	:checkhealth straps
<
Diagnoses everything that can be wrong before a session runs: the Neovim
version, `curl` (and optional ripgrep), the API key (including a group/other
readable key file), a writable `session_dir`, the tree-sitter `straps` parser
and its queries, the `.straps.lua` trust state, the loaded registry (entry
counts, redefinitions, missing core entries), the model/effort pairing, and
any runs still in flight. Every probe is isolated, so the report runs even
when `setup()` never ran or the data dir is unwritable.
